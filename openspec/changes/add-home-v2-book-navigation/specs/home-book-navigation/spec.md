## ADDED Requirements

### Requirement: 首页 V2 使用书本式双页壳作为主容器
系统 SHALL 为首页 V2 提供书本式双页壳，并以该壳作为移动端 App 首页的主内容容器，而不是继续采用普通平面列表页作为最终组织方式。

#### Scenario: 首页首次进入显示书本主容器
- **GIVEN** 用户打开移动端 App 并进入首页
- **WHEN** 首页 V2 初始化
- **THEN** 系统 MUST 显示书本式主容器
- **AND** 后续首页主要内容 MUST 渲染在书页安全区内

#### Scenario: 视觉校准阶段先只保留书本壳
- **GIVEN** 首页 V2 仍处于书本尺寸、透视、安全区和书签位置的校准阶段
- **WHEN** 视觉基准尚未被确认
- **THEN** 系统 MUST 先只保留背景、书本序列帧和书签序列帧
- **AND** MUST NOT 在书页上叠加占位性质的原生 HTML/CSS 卡片、按钮、榜单或房间列表

### Requirement: 首页进入时播放开书动画并并行预加载首屏数据
系统 SHALL 在首页首次进入时播放开书动画，并与首页首屏最小数据的预加载并行执行。

#### Scenario: 开书与首屏加载并行
- **GIVEN** 用户首次进入首页 V2
- **WHEN** 系统开始渲染首页
- **THEN** 系统 MUST 播放开书动画
- **AND** MUST 在动画期间并行拉取首页首屏所需最小数据
- **AND** 开书完成后首页首个目录页 SHOULD 已进入可交互状态

### Requirement: 首页大厅目录页采用双页分页结构
系统 SHALL 将首页大厅组织为可翻页的目录页，而不是把所有游戏一次性铺满为单张长列表。

#### Scenario: 大厅页展示当前目录分页
- **GIVEN** 用户处于首页大厅目录页
- **WHEN** 页面渲染完成
- **THEN** 系统 MUST 使用双页布局展示当前目录分页
- **AND** 目录分页 MUST 支持通过翻页切换上下页

### Requirement: 点击游戏后通过翻页进入详情页
系统 SHALL 在用户从大厅目录进入某个游戏时，使用翻页过渡进入游戏详情页。

#### Scenario: 从大厅进入游戏详情
- **GIVEN** 用户位于大厅目录页
- **AND** 当前页中存在可点击的游戏条目
- **WHEN** 用户点击某个游戏
- **THEN** 系统 MUST 播放翻页过渡
- **AND** MUST 进入该游戏的详情页

### Requirement: 游戏详情页左侧展示描述，右侧展示房间列表
系统 SHALL 为游戏详情页提供稳定的双页职责分配：左页负责描述与入口，右页负责房间列表。

#### Scenario: 游戏详情页显示双页职责分配
- **GIVEN** 用户位于某个游戏详情页
- **WHEN** 页面渲染详情内容
- **THEN** 左页 MUST 展示该游戏的描述与主要入口
- **AND** 右页 MUST 展示该游戏的房间列表或对应的空状态

### Requirement: 详情页支持左翻回大厅，右翻进入下一个游戏
系统 SHALL 在游戏详情页中提供稳定的左右翻页语义，用于返回大厅和切换相邻游戏。

#### Scenario: 详情页左翻返回大厅
- **GIVEN** 用户位于某个游戏详情页
- **WHEN** 用户执行向左翻页
- **THEN** 系统 MUST 返回大厅目录页

#### Scenario: 详情页右翻进入下一个游戏
- **GIVEN** 用户位于某个游戏详情页
- **WHEN** 用户执行向右翻页
- **THEN** 系统 MUST 进入下一个游戏的详情页

### Requirement: 首页 V2 使用右侧书签承载高层入口切换
系统 SHALL 使用书本右侧书签承载首页的高层入口切换，而不是把书签做成游戏分类筛选器。

#### Scenario: 书签切换首页高层入口
- **GIVEN** 用户位于首页 V2
- **WHEN** 用户点击右侧书签
- **THEN** 系统 MUST 切换到对应的首页高层入口页
- **AND** 这些入口 MUST 优先复用当前首页已经存在的标签页与首页悬浮球功能
- **AND** 这些入口 SHOULD 优先包括大厅、房间、排行榜、更新、作者等首页级入口
- **AND** MUST NOT 把右侧书签降级为“全部 / 双人 / 多人 / 教学 / 本地”这类单纯分类筛选
- **AND** MUST NOT 提前把创建房间相关的模组/包管理 UI 搬到首页书签上

### Requirement: 首页 V2 直接进入实施阶段而不是只做视觉校准
系统 SHALL 在校准书本比例、书页安全区和书签对位的同时，直接推进首页主交互实施，而不是停在纯壳体校准阶段。

#### Scenario: 实施阶段同步推进视觉与交互
- **GIVEN** 首页 V2 已经具备可运行的逐帧书本壳基线
- **WHEN** 后续实现继续推进
- **THEN** 系统 MUST 同步推进书本校准和首页主交互实施
- **AND** MUST 不把“只做尺寸校准、不做真实首页入口”当作默认交付目标

### Requirement: 首页 V2 的交互组织参考炉石式游戏首页
系统 SHALL 采用更接近炉石首页的交互组织方式，让首页入口围绕核心游戏体验展开，而不是做成工具台或后台面板。

#### Scenario: 首页入口以游戏体验为主
- **GIVEN** 用户进入首页 V2
- **WHEN** 首页主要入口被组织到书页与书签上
- **THEN** 系统 MUST 优先突出进入大厅、查看房间、查看排行、查看更新等游戏相关入口
- **AND** SHOULD 采用类似炉石首页那种“主入口明确、辅助入口围绕主玩法展开”的交互节奏

### Requirement: 首页 V2 的视觉风格以游戏为主
系统 SHALL 让首页 V2 的视觉表达以游戏氛围和游戏入口为主，而不是偏管理台、工具页或表单页。

#### Scenario: 首页整体视觉以游戏内容为中心
- **GIVEN** 首页 V2 完成主视觉与交互布局
- **WHEN** 用户查看首页
- **THEN** 系统 MUST 让首页整体更像游戏首页而不是后台工具页
- **AND** 书本中的主要关注点 SHOULD 落在游戏入口与游戏内容，而不是杂项控制面板

### Requirement: 首页 V2 以移动端横屏为主方向
系统 SHALL 以移动端横屏作为首页 V2 的主设计与主验收方向。

#### Scenario: 横屏进入首页 V2
- **GIVEN** 用户在移动端横屏进入首页 V2
- **WHEN** 首页完成渲染
- **THEN** 书本双页布局 MUST 作为主形态呈现
- **AND** 背景 MUST 铺满整个横屏视口
- **AND** 书本主体 SHOULD 占据接近满屏的主视觉比例，而不是缩在中央小块区域

#### Scenario: 竖屏进入首页 V2
- **GIVEN** 用户在移动端竖屏进入首页 V2
- **WHEN** 当前没有竖屏专用书本布局
- **THEN** 系统 MAY 使用旋转提示、简化单页或其他明确降级方案
