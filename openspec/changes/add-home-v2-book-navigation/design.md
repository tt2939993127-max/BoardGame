## Context

首页 V2 主要服务移动端 App，而不是沿用当前网页首页的普通标题 + 筛选 + 列表结构。用户希望首页像一本书：

- 启动后先看到背景与开书动画
- 动画期间后台加载首页首屏数据
- 开书完成后进入“大厅目录页”
- 点击游戏后通过翻页进入详情页
- 详情页左翻回大厅，右翻进入下一个游戏

当前已在 `temp/Super Asset Bundle #2 - Adventure Time v1.5/Updated Paper Book/Sprites/` 下找到完整的书本素材包，可用于本次首页 V2 方案建模。

## Goals

- 首页 V2 以书本式阅读器作为唯一主容器，而不是给旧首页简单换皮。
- 进入首页时使用真实开书动画，同时把动画作为首屏数据的感知加载窗口。
- 大厅目录页与详情页都使用双页布局，并支持左右翻页。
- 首页 V2 以移动端 App 横屏为主验收方向。
- 右侧真实书签优先承载当前首页已有标签页与首页悬浮球已覆盖的首页级功能。
- 首页 V2 的整体气质与交互组织要更接近“游戏首页”，而不是工具台。
- 在 spec 中明确可用素材和真实缺口，避免实现阶段误判资源边界。

## Non-Goals

- 本次不直接替换旧首页实现，只先完成 spec 与草图。
- 本次不把所有按钮、列表项、房间卡全部做成纯像素素材拼装。
- 本次不承诺竖屏完整双页体验；竖屏只作为降级或旋转提示候选。
- 本次不处理首页以外的局内 UI 改造。

## Decisions

### Decision: 首页 V2 先锁定“全屏背景 + 大比例书本壳 + 真实书签位置”，但不止停在校准

当前阶段的首要目标不是往书页里填业务块，而是先把以下视觉基线校准正确：

- 背景必须铺满整个移动端横屏视口
- 书本主体必须接近满屏，而不是缩成中央小物件
- 右侧真实书签的位置、数量和露出比例必须先对准素材本体

在这三件事未通过前，不再接受把大量原生 HTML/CSS 占位 UI 压到书页上“先看个意思”的做法。
但这不等于后续只做校准不做实施。正确路径是：先把这三项拉到可用基线，然后立刻开始把首页真实入口按新结构接进去。

### Decision: 下一阶段 UI 风格匹配先收敛成“单书 + 左页 2×2 卡片”基线

下一阶段先不追求把所有首页入口一次收满，而是先把当前大厅主入口做成一个稳定基线：

- 书本是唯一内容主体，卡片父容器必须挂在书页内部，而不是挂在书外再压到书面上
- 当前大厅入口先只做左页内容，不在这一步恢复分类筛选、右页业务块或额外解释文案
- 左页只保留 4 张真实游戏卡，按 2×2 均匀填入左页内框
- `tool` 类型条目不进入这组卡片
- 卡片继续沿用现有大厅卡片样式；这一轮只允许做缩放、内边距、底板和配色收口，不允许私自换成另一套简陋 UI

这一步的目标是先把“内容真的长在书里，而且风格没跑偏”做对。

### Decision: 首页 V2 采用“书本壳 + 双页内容”而不是旧首页换皮

首页 V2 SHALL 以书本素材作为主交互骨架：

- 背景层负责舞台氛围
- 书本层负责开书、静止、翻页
- 页内内容层承载真实 HTML 内容

这意味着首页 V2 的实现重点是“书本状态机”，不是继续沿用现有 [`Home.tsx`](D:/gongzuo/webgame/BoardGame-wt-home-v2/src/pages/Home.tsx) 的平面列表布局再套一层背景图。

### Decision: 运行时只能存在一套书本状态机，不允许出现第二本书

首页 V2 的运行时裁决如下：

- `open / tabs / ready / flip-*` 都是同一本书在不同状态下的表现
- 背景层可以有桌面、阴影、氛围，但不能再额外渲染一张“常驻静态书”造成双书叠加
- 翻页必须发生在同一个书本实例上，而不是在别处临时播放另一套翻页资源

这条裁决直接服务于“像游戏里的单个场景对象”，而不是网页式多层拼贴。

### Decision: 首页进入时的开书动画与首屏数据预加载并行

系统 SHALL 在首页首次进入时并行执行两类工作：

- 前台：播放背景出现与开书动画
- 后台：拉取首页首屏所需最小数据

最小数据至少包括：

- 游戏目录元数据
- 当前用户继续对局摘要
- 首个目录页所需的缩略信息

不要求等待全量数据加载完成后才允许开书，但开书完成时首个目录页 SHOULD 已可用。

### Decision: 大厅目录页与游戏详情页都采用双页结构，并在校准同时直接重建真实首页入口

大厅目录页布局：

- 左页：品牌、继续对局、分类摘要、少量说明
- 右页：当前目录页的游戏条目

游戏详情页布局：

- 左页：描述、标签、支持人数、入口按钮
- 右页：房间列表

补充裁决：

- 在书页安全区、留白、透视和按钮真实落点没有确认前，页内原生 UI 应先全部清空。
- 下一位实现者应基于已确认的书页安全区直接放入“更少、更克制、但真实可用”的首页入口，而不是恢复这轮被清掉的大量草稿占位块。
- 真正开始做 UI 风格匹配时，目录页先只要求左页内框完成 2×2 卡片排布并通过几何验收。
- 右页、书签页、详情页延续现有状态机与配色方向，但不要求和左页卡片基线在同一轮一起收口。

### Decision: 翻页承担主要导航语义

翻页语义 SHALL 固定如下：

- 大厅目录页左右翻：切换目录分页
- 点击游戏：翻页进入对应游戏详情
- 详情页左翻：返回大厅目录页
- 详情页右翻：进入下一个游戏详情

后续如果需要循环浏览，可在实现阶段决定“最后一个游戏继续右翻时是循环还是停住”，但 spec 当前只定义主方向语义。

### Decision: 书签负责复用当前首页已有标签页与悬浮球功能

右侧书签 SHOULD 优先承载以下入口：

- 大厅
- 房间 / 活跃对局
- 排行榜
- 更新
- 作者 / 资料来源

书签应优先复用当前首页已经存在的标签页与首页悬浮球所对应的首页级功能。

书签不应被降级成“全部 / 双人 / 多人 / 教学 / 本地”这类游戏分类切换，也不应提前塞入“创建房间才需要的模组/包管理 UI”这类当前不属于首页主入口的内容。

### Decision: 交互节奏参考炉石式游戏首页

首页 V2 的组织方式应更接近炉石首页：

- 主入口明确，先看到最核心的游戏去向
- 次级入口围绕主玩法展开，而不是平铺成工具页
- 用户进入后能快速理解“先去哪玩、还能看什么”

这并不是要求复制炉石视觉，而是要求首页信息架构和入口优先级具备相似的游戏导向。

### Decision: 视觉风格以游戏为主，而不是管理台或工具页

首页 V2 的气质裁决如下：

- 以游戏氛围、游戏入口、游戏状态为主
- 少做后台卡片、工具面板、表单味很重的块
- 即使后续接入排行/更新/作者，也应仍然服务“这是一个游戏首页”的整体感受

### Decision: 书本舞台与页内卡片的验收以几何边界为准

下一阶段 UI 验收不再靠“看起来差不多”，而是直接以书页内框边界做判断：

- 背景负责铺满整个视口，但不作为书本尺寸判断依据
- 书本主体高度 SHOULD 达到视口高度的约 90%，宽度按素材原始比例自适应
- 书本整体需要继续上移并保持垂直居中，以“上下留白接近”作为主观校验标准
- 左页内容必须全部位于左页内框之内；当前素材下可直接以书页内层描边/色块区域作为边界
- 左页内容不得越过书脊中线
- 缩略图必须保持原始比例；优先缩小高度，不允许为铺满容器而横向拉伸
- 翻页期间必须隐藏附加 UI，避免内容悬浮在翻页书面上的假象

### Decision: 首页 V2 主方向为移动端横屏

由于当前书本主素材全部为 `896x720` 的双页构图，首页 V2 MUST 以移动端横屏作为主设计与验收方向。竖屏若未找到更合适的单页素材，则可采用以下策略之一：

- 旋转提示
- 简化单页降级
- 保留旧首页作为竖屏 fallback

本轮 spec 不把竖屏双页体验定义为必须完成项。

### Decision: 首页 V2 在 App 壳内必须有原生层方向声明

首页 V2 不是 `/play/:gameId` 游戏页，因此不能天然复用现有“游戏页按 manifest 锁方向”的原生链路。

若首页 V2 要在 Android / App WebView 中被视为真正的横屏首页，系统 MUST 满足以下条件：

- 原生 `MainActivity` 能识别首页 V2 路由，或能读取构建产物中的首页方向元数据；
- 原生层先把 Activity 切到横屏，再由 H5 层进行补充锁定与重试；
- 不能只依赖 `MobileOrientationGuard` 或前端 `screen.orientation.lock(...)` 来宣布“首页已强制横屏”。

结论：首页 V2 的方向控制必须与游戏页一样，拥有原生层的明确方向入口，而不是停留在 H5 意图层。

## Known Gaps

### 可用 HTML/SVG/CSS 补位的缺口

1. **页内业务控件**
   - 当前素材没有完整覆盖“房间列表项、CTA 主按钮、描述信息块”的所有业务态。
   - 这部分应由 HTML/SVG/CSS 在页内安全区实现，而不是强求全像素拼图。

2. **书签激活/选中态**
   - 现有书签有静态基底和出现/消失动画，但没有明确的“激活中/禁用中/计数角标”全套状态。
   - 可以先用 HTML 文本、颜色描边或小型 SVG 标识补位。

3. **自定义书签语义图标**
   - 素材包自带的 `With icons` 书签图标更偏通用 RPG inventory，不一定适配“全部/双人/多人/教学/本地/实验”。
   - 若你希望每个书签都有更贴合桌游平台语义的专用图标，建议补一套图标参考或交给实现阶段用 SVG 重绘。

### 可能需要额外素材的缺口

1. **竖屏专用单页书**
   - 如果首页 V2 最终要求移动端竖屏也以书本为主形态，当前双页 `896x720` 素材并不理想。
   - 这时更适合补一套单页书、半开书或竖屏封面素材。

2. **更强的详情页层级装饰**
   - 如果你希望详情页左侧描述和右侧房间列表都有更明显的纸片底板、章节头、页码牌、分隔饰条，当前素材包不够完整。
   - 现阶段可以用 SVG 补，但如果要统一成同风格像素件，后续仍可补素材。

## Implementation Notes

- 本轮已将首页 V2 素材正式迁入 `public/assets/common/images/home-v2/`，并保留原始 `png` 与 `compressed/*.webp` 运行时产物。
- 首页 V2 当前已裁定使用逐帧图方案，不再把“是否用 sprite sheet”留作本轮待定项。
- 通用逐帧底层已落在 `src/components/common/animations/frameSequence.ts` 与 `src/components/common/animations/FrameSequencePlayer.tsx`，后续其他游戏或通用 UI 也可直接复用。
- 本轮已明确回滚书页上的原生草稿 UI，只保留全屏背景、开书、书签出现和静止书本壳，作为下一位实现者的干净基线。
- 下一位实现者应基于这个基线边校准边实施：
  - 书本最终放大比例
  - 书页安全区矩形
  - 右侧书签命中区与标签文案对位
  - 复用现有首页标签页 / 悬浮球能力的最小真实入口页
- 下一阶段若只做 UI 风格匹配，应优先按以下顺序推进：
  1. 重构成单书状态机，去掉双书叠层
  2. 把书本放大到约 `90vh` 并重新做垂直居中
  3. 用左页内框作为唯一容器，塞入 4 张非 `tool` 游戏卡
  4. 保持现有卡片视觉样式，只做缩放、内边距、底板和配色收口
  5. 用截图和几何数据证明“全在左页内、全未越中线”
