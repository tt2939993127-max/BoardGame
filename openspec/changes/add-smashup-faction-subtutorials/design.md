## Context
- 当前教程系统以单个 `TutorialManifest` 为主：运行时缓存、路由判断、`MatchRoom` 启动逻辑默认一个游戏只会有一份教程。
- 大杀四方派系详情已经有标题、描述、变体切换和卡牌预览，但没有任何机制教学入口。
- 用户要求入口“直接放标题右侧，不要多余占位”，说明入口必须是按需渲染，而不是预留固定槽位。

## Goals
- 让教程系统支持“默认教程 + 子教程”而不破坏现有游戏。
- 支持从明确路由直接进入子教程，便于从 UI 入口或外部链接跳转。
- 让大杀四方派系详情可按派系显示机制教程入口。
- 首个案例完整落地牛仔决斗教程。

## Non-Goals
- 不在本次引入通用教程目录列表页。
- 不重做现有各游戏主教程脚本结构。
- 不为没有机制教程的派系制造禁用按钮、空白占位或统一占位文案。

## Decisions

### 1. 用“教程目录”包装单教程导出
- 新增教程目录类型，例如：默认教程 ID + `Record<tutorialId, TutorialManifest>`。
- 运行时加载层统一把“旧单教程”规范化成只含默认教程的目录，避免其他游戏批量改造。
- `MatchRoom` 根据路由参数解析目标 `tutorialId`，再从目录中取出对应 manifest 启动。

### 2. 路由显式携带 `tutorialId`
- 保留 `/play/:gameId/tutorial` 作为默认教程入口。
- 新增 `/play/:gameId/tutorial/:tutorialId` 作为子教程深链入口。
- 这样不会污染 query string，也方便从任意 UI 入口直接导航。

### 3. 派系详情入口由游戏层元数据控制
- 不把“哪些派系有哪些教程”写死在通用教程系统里。
- 大杀四方在自己的派系元数据/教程元数据层维护映射：某个派系组关联哪些子教程。
- `FactionSelection` 只消费“当前聚焦派系是否存在入口”这一真值，按需渲染标题右侧按钮。

### 4. 子教程仍沿用现有 TutorialManifest 机制
- 牛仔决斗教程继续使用现有 `TutorialManifest` 步骤、命令白名单、事件推进、AI 动作等能力。
- 不额外发明“轻教程 DSL”；若后续出现大量机制教程，再在后续变更里抽象工厂。

## Risks / Tradeoffs
- 教程目录一旦接入路由和缓存，若回退逻辑不清晰，容易出现“深链 tutorialId 不存在却静默进了默认教程”的误导；需要明确处理口径。
- `MatchRoom` 当前用 `window.location.pathname.endsWith('/tutorial')` 判断教程模式，接入子路由后必须改成基于 params/路由语义的判断，否则子教程不会生效。
- 大杀四方派系详情是复杂自适应布局，标题右侧新增入口后需要同时检查移动横屏与桌面，不得破坏原有标题换行与关闭按钮层级。

## Validation Plan
- 静态/单测：教程目录规范化、路由解析、无效 tutorialId 行为、派系详情入口显示条件。
- 游戏级测试：牛仔决斗教程脚本的关键步骤与允许命令/推进事件。
- E2E：从大杀四方派系详情点击入口进入牛仔决斗教程，验证真实链路与截图证据。
