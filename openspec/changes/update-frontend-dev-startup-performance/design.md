## Context

当前的缓存目录已按工作目录和端口隔离，因此保留同端口缓存不会在并行 Vite 服务之间共享可变状态。问题来自启动包装器无条件删除该缓存，以及桌面入口静态连通原生模块树。

## Goals / Non-Goals

- Goals: 缩短重复开发启动和桌面首屏模块转换；保留原生移动初始化；不引入第二套配置真相。
- Non-Goals: 不更换 Vite/React，不改变 API 代理、HMR 策略、游戏数据或房门配置，不把不同端口合并为共享缓存。

## Decisions

- 缓存清理由默认行为改为显式 `BG_VITE_CLEAN_DEPS_ON_START=1` 请求；默认值复用现有按端口缓存目录。
- 移动运行时检测只读取原生壳已注入的窗口桥接信号，避免桌面入口静态导入 Capacitor。需要原生插件的模块在检测为原生后通过动态导入加载。
- 不配置 `server.warmup.clientFiles`。实测入口会展开过宽的静态模块图，预热会阻塞 HTTP 响应；应先缩小桌面静态依赖图，再让 Vite 按真实访问按需转换。
- `STABLE_OPTIMIZE_DEPS` 是开发和 E2E 共用的唯一依赖预构建清单。两种模式均禁用自动发现；清单只保留浏览器兼容所需的关键依赖，避免空缓存时扫描完整源码图。
- `BG_DEV_DISABLE_HMR` 与 `BG_DEV_DISABLE_HOT_RELOAD` 统一派生 `disableViteWatch`。关闭 HMR 后保留每秒轮询没有用户价值，且会扫描大型工作目录并抢占 HTTP 请求处理。
- 经典首页的详情弹窗保持用户点击时加载；只有原生移动壳才在空闲期预取它。版本页脚保留桌面版本显示，但其 OTA 读取与订阅只在 Android 原生壳中动态加载。
- 首页通过路由级 `React.lazy` 加载，并有明确加载层。非首页路由不再同步导入 `HomeEntry` 与首页目录；首页自身则先完成应用壳挂载，再按需解析目录模块。
- 配置表的路径与页面映射集中在 `ConfigReviewRoutes`。完整应用和轻量配置表入口共用该映射，防止新增或调整游戏配置表时产生两套路由真相。
- Tailwind 以 `source(none)` 关闭工作区自动检测，再从 `src/index.css` 显式登记 `.` 作为唯一运行时源码根。实测此变更保持近似的 CSS 输出体积，同时把独立 CSS 编译从约 99 秒缩短到约 3.4 秒。

## Risks / Trade-offs

- 旧缓存可能在依赖或 Vite 配置变更后失效；此时开发者可显式请求清理，Vite 自身也会在依赖优化需要时重建。
- 原生桥注入异常会使移动初始化不执行；保留并扩展运行时诊断测试，且原生壳的 Android/iOS 桥接信号仍是唯一检测真相。

## 配置表入口边界

配置表不是大厅、对局或移动壳的子功能。它需要浏览器路由、鉴权、反馈提示和配置页面本身，但不需要社交连接、教程状态、测试注入、全局悬浮菜单、移动方向锁或游戏救援层。

因此入口选择在 `main.tsx` 根据共享的配置表路径判断完成：配置表加载 `ConfigReviewApp`，其他路径加载完整 `App`。`ConfigReviewRoutes` 是三个游戏配置表的唯一页面映射，两个应用壳都消费它；这只拆运行壳，不复制路径或页面定义。

## Migration Plan

1. 修改启动缓存和入口加载，避免预热完整桌面模块图。
2. 验证类型、移动运行时诊断与真实桌面请求图。
3. 回到首页和小黑屋配置表验证真实入口。
