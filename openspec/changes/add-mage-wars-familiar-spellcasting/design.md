# 设计：魔宠与再生点独立施法

## 真相源

- 规则书第 13 页：具有施法能力的生物可以施放已准备的快速 / 标准法术。
- 规则书第 18 页：魔宠在计划阶段额外选择一张法术；魔宠行动阶段施放；魔宠先支付自身法力，再由控制法师补足；魔宠作为施法者计算范围。
- 规则书第 18 页：再生点在计划阶段额外选择一张法术；部署阶段施放；再生点先支付自身法力，再由控制法师补足；再生点作为施法者计算范围。
- Workshop 对照源：巢穴 `2218`、乌鸦魔宠胡金 `2908`、花仙魔宠菲蕾拉 `2905`、灵婴魔宠瑟希利克斯 `3017`。CardID 只是索引证据，正式接入前仍需逐卡字段与 atlas/frame 核对。
- 来源卡字段与 frame 合同：`docs/games/mage-wars/rule/familiar-spellcasting-card-contract.md`。该合同已锁定四张卡的核读结果，并明确首批接入候选与延后候选，不替代正式运行时配置。

## Owner 边界

- 配置包 owner：声明对象的施法来源类型、可准备法术限制、施法阶段和聚魔 / 法力上限。
- 计划领域 owner：记录对象的单张计划法术，并保证它与法师的计划槽独立。
- 施法领域 owner：验证对象是当前控制者、对象仍在场、计划牌确实属于该对象，并按对象位置计算范围。
- 资源结算 owner：先扣对象法力，再扣控制法师法力；取消 / 反制时只返还实际扣除的资源。
- 响应系统 owner：响应 frame 只保存结构化施法者与对象计划引用，不复制另一份施法主状态。
- `1804` owner：只消费成功的 `SPELL_CAST_RESOLVED`，从当前对象关系查找附属来源并生成直接伤害。

## 状态模型

`MageWarsArenaObjectState` 增加对象施法所需的最小状态：

- `mana`：对象自己的法力指示物数量。
- `preparedSpellCardId`：本回合为该对象选择的唯一法术；对手视图只暴露卡背 / 数量。
- `spellcastingSource`：结构化来源，至少区分 `familiar` 与 `spawn-point`，并包含配置能力 ID。

玩家的 `preparedSpellCardIds` 继续只表示法师计划牌，不把对象计划牌塞入其中。

## 命令与时序

1. 计划阶段提交玩家计划和对象计划；每个合法施法对象最多一张，卡牌类型和来源限制由配置校验。
2. 魔宠只在其生物行动阶段施放，消耗其快速 / 标准行动；再生点只在部署阶段施放。
3. 命令必须显式传对象 ID；解析出的 `MageWarsSpellCasterRef` 写入开始事件、响应上下文和成功事件。
4. 施法校验使用对象区域而不是控制法师区域计算范围；不存在对象计划、对象离场或行动时机不符时拒绝。
5. 先生成对象法力扣除，再生成控制法师补足扣除；响应反制 / 取消时恢复已扣资源并按规则处理计划牌。
6. 仅在成功 `SPELL_CAST_RESOLVED` 后触发附属 `1804`；被反制、取消、来源离场或验证失败均不触发。

## 非目标

- 不把所有 `creature` 自动视为魔宠。
- 不把 `targetObjectId`、`sourceObjectId` 或 `playerId` 猜作实际施法者。
- 不把 Workshop 候选 CardID 直接当作已核对的正式卡牌字段或 atlas frame。
- 不在本 change 中实现完整 322 张法术、自由构筑、四人模式、完整 UI 或多人响应优先级。

## 风险与缓解

- 卡牌字段仍可能存在同名 / 多 frame 候选：先完成逐卡字段合同，再进入配置包。
- 取消与来源销毁的返还语义容易混淆：用事件表测试“已支付 / 已取消 / 来源先被摧毁”三条独立路径。
- 对手隐藏信息不能泄露对象计划牌：player view 只输出对象是否有计划和卡背引用。
