## MODIFIED Requirements

### Requirement: 游戏详情独立更新标签
系统 SHALL 在游戏详情弹窗中提供独立的“更新”标签，用于展示该游戏已发布的更新日志。

#### Scenario: 切换到更新标签
- **WHEN** 用户在游戏详情弹窗中切换到“更新”标签
- **THEN** 系统 MUST 请求该游戏的公开更新日志接口
- **AND** MUST 只渲染已发布日志

#### Scenario: 更新日志为空
- **WHEN** 当前游戏没有任何已发布更新日志
- **THEN** “更新”标签页 MUST 显示空状态说明

#### Scenario: 更新日志加载失败
- **WHEN** 更新日志公开接口请求失败
- **THEN** “更新”标签页 MUST 显示错误状态
- **AND** MUST 记录错误日志

### Requirement: 移动端详情页必须提供左下角包管理操作区
系统 SHALL 在移动端游戏详情页左下角提供固定的包管理操作区，用于安装、更新和恢复当前游戏所需的移动端包。

#### Scenario: 移动端显示左下角安装入口
- **GIVEN** 用户在移动端打开某个 `package-managed` 游戏的详情页
- **WHEN** 详情页完成渲染
- **THEN** 系统 MUST 在详情页左下角展示独立的安装/更新操作区
- **AND** 该区域 MUST 以 overlay 方式贴边显示，不得挤压详情正文的主布局

#### Scenario: 移动端显示下载中状态
- **GIVEN** 用户已触发当前游戏的安装或更新
- **WHEN** 包下载、校验或安装正在进行
- **THEN** 左下角操作区 MUST 显示进行中状态
- **AND** MUST 明确告知当前操作作用于“当前游戏”

#### Scenario: 移动端显示错误与重试
- **GIVEN** 当前游戏包的下载、校验或激活失败
- **WHEN** 用户仍停留在该游戏详情页
- **THEN** 左下角操作区 MUST 显示失败状态
- **AND** MUST 提供重试入口
- **AND** 不得把错误状态错误归因到其他游戏
