# 设计：反戈一击结构化附属结界

## Owner 边界

- `mage-wars.config.json` 保存 `1903` 的静态附属结界和授予特性事实。
- `configPackage.ts` 负责严格读取新的授予特性枚举。
- `spellRules.ts` 负责从可见附属结界来源解析反击资格，并保留守卫 / 展示文本夹具路径。
- `events.ts`、`execute.ts` 和 `systems.ts` 负责把来源结界带过反击交互、可能的防御窗口，并在反击真正执行或被防御结算后消费来源。

## 配置形状

`1903` 使用已有可见对象结界容器，不新增第二套附属对象模型：

```json
{
  "requiresCodeSupport": false,
  "semantics": {
    "abilityKind": "visible-object-enchantment",
    "attachment": {
      "kind": "enchantment",
      "visibility": "revealed",
      "anchor": "object"
    },
    "grants": [
      { "trait": "counterstrike" }
    ]
  }
}
```

`counterstrike` 不使用数值字段。运行时来源对象 ID 是一次性消费的事实，不能由展示文本或卡牌名称重新推导。

## 反击来源裁决

1. 近战攻击、敌对同区、目标为存活生物和防眩晕等既有资格条件不变。
2. 守卫反击优先保留；若守卫生物同时附有 `1903`，同一次选择携带该结界来源，以便首次反击后消费。
3. 非守卫目标先使用自身卡牌结构化反击特性；若没有，再使用可见附属结界授予的 `counterstrike`；最后保留未配置夹具的“反击”展示文本解析。
4. 选择放弃不消费来源。
5. 选择反击后，若反击进入防御窗口，来源 ID 随防御交互传递；防御成功、攻击失手、攻击造成伤害或攻击因免疫而失效，都视为这次反击已经执行并消费来源。

## 非目标

- 不把所有卡牌级特性一次性抽象成新的通用能力系统。
- 不改变守卫反击的交互形式、行动消耗、递归边界和防御规则。
- 不让 `1903` 的展示文案成为结构化运行时的必要输入。
