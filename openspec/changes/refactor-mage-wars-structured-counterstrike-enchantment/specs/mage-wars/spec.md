## ADDED Requirements

### Requirement: Structured Counterstrike Enchantment

`1903` 反戈一击 SHALL expose its granted counterstrike behavior through visible-object-enchantment semantics rather than display text.

#### Scenario: Configured enchantment grants counterstrike without display text

- **GIVEN** a configured `1903` enchantment is revealed and attached to a living creature
- **AND** the enchantment and creature display text may be empty or rewritten
- **WHEN** an enemy melee attack targets that creature and the creature is otherwise eligible for counterstrike
- **THEN** the runtime MUST surface the existing counterstrike choice
- **AND** the event MUST retain the attached enchantment instance as the source

#### Scenario: First executed counterstrike consumes the enchantment

- **GIVEN** the counterstrike choice came from an attached `1903` enchantment
- **WHEN** the defender chooses counterstrike
- **THEN** the runtime MUST resolve the existing quick melee counterstrike path
- **AND** the runtime MUST destroy that attached enchantment instance exactly once

#### Scenario: Defense resolution still consumes the source

- **GIVEN** a selected `1903` counterstrike enters the existing defense response window
- **WHEN** the defense succeeds, fails, or is passed
- **THEN** the counterstrike source enchantment MUST be consumed after that response path completes
- **AND** no second counterstrike opportunity may be generated by the counterstrike attack

#### Scenario: Passing preserves the enchantment

- **GIVEN** a counterstrike opportunity sourced from `1903`
- **WHEN** the defender chooses pass
- **THEN** the attached enchantment MUST remain in play
- **AND** the original attack flow MUST remain unchanged

### Requirement: Counterstrike Migration Boundary

The change SHALL preserve existing counterstrike owners outside `1903`.

#### Scenario: Guard and text fixtures remain compatible

- **GIVEN** a guarding creature or an unconfigured test fixture uses the existing guard / display-text counterstrike path
- **WHEN** it becomes eligible for counterstrike
- **THEN** the existing source ability and interaction behavior MUST remain available
- **AND** no unrelated card-level trait is claimed as migrated by this change
