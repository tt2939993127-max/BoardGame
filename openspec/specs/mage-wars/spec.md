# 法师战争

## Purpose

定义 Mage Wars 学徒模式从正式入口、配置包、领域玩法到真实端到端验收的当前能力边界，避免把 foundation、布局截图或状态注入测试误报为完整新游戏。

## Requirements

### Requirement: 学徒模式开局
系统 SHALL 提供两人学徒模式的正式游戏开局，使用 2x3 竞技场、四名学徒法师配置和规则规定的 24 点初始生命。

#### Scenario: 从正式入口创建学徒对局
- **WHEN** 两名玩家从正式 Mage Wars 入口进入对局
- **THEN** 系统 MUST 创建两名玩家、六个竞技场区域和各自的预设学徒法术书
- **AND** 两名法师的初始生命 MUST 为 24
- **AND** 玩家初始位置 MUST 来自配置包而不是 UI 临时常量

### Requirement: 配置包驱动静态事实
系统 SHALL 从严格 JSON 配置包提供学徒法师、法术书、学徒法术牌、竞技场区域、正式图集引用、骰子和 token 的静态事实。

#### Scenario: 配置与运行时一致
- **WHEN** 运行时查询学徒法师、法术书或法术牌
- **THEN** 查询结果 MUST 能回到 `src/games/mage-wars/data/mage-wars.config.json`
- **AND** 卡牌素材 MUST 使用正式 atlas/frame 引用
- **AND** 未实现的特殊效果 MUST 明确标记为代码能力缺口，不能仅凭卡面文字宣称可执行

### Requirement: 核心回合玩法
系统 SHALL 支持学徒模式的重置、聚魔、维持、计划、部署、快速施法、魔物行动和最终快速施法阶段，并通过领域命令与事件推进状态。

#### Scenario: 玩家完成一条核心行动链
- **WHEN** 当前玩家在正式页面选择法术、选择合法目标并施放
- **THEN** 页面 MUST 发出真实领域命令
- **AND** 领域层 MUST 校验阶段、行动标记、法力、射程和目标规则
- **AND** 页面 MUST 反映法力、计划牌、弃牌、场地对象或伤害状态的变化

#### Scenario: 玩家完成攻击链
- **WHEN** 当前玩家从合法行动来源选择攻击并选择合法目标
- **THEN** 系统 MUST 经过攻击声明、骰子/防御响应和伤害结算
- **AND** 攻击骰、效果骰、伤害和状态 token MUST 使用真实事件结果
- **AND** 回合结束后 MUST 进入下一合法阶段或下一玩家回合

### Requirement: 真实交互端到端覆盖
系统 SHALL 以正式入口和真实玩家交互作为 Mage Wars 可交付性的验收依据。

#### Scenario: 核心玩法 E2E 不注入核心状态
- **WHEN** 执行 Mage Wars 核心玩法 E2E
- **THEN** 测试 MUST 从正式入口创建或进入对局
- **AND** 测试 MUST 通过页面交互或正式命令入口完成计划、施法/目标、攻击/骰子、伤害/状态和回合推进
- **AND** 测试 MUST NOT 使用测试 harness 直接 patch 核心游戏状态来代替上述玩法链

#### Scenario: 隐藏信息和正式素材保持有效
- **WHEN** 对手查看己方未揭示的计划牌或隐藏结界
- **THEN** 对手 MUST 只能看到规则允许的牌背/数量信息
- **AND** 验证 MUST 同时确认标准竞技场、法师牌、法术牌、骰子和 token 的正式资源确实加载

### Requirement: 明确的未交付范围
系统 MUST 将尚未纳入本轮的内容标记为后续 change，不得把 foundation 或学徒玩法收口误报为完整 Mage Wars。

#### Scenario: 完成状态汇报保持边界
- **WHEN** 当前实现只完成学徒模式或部分卡牌能力
- **THEN** 完成汇报 MUST 明确说明全 322 张法术、自由构筑、四人模式、豪华竞技场、扩展法师、完整 AI、教程、行动日志 UI 和撤回 UI 是否仍未交付
- **AND** 布局截图、静态单测或状态注入型 E2E MUST NOT 单独作为整款游戏完成证据
