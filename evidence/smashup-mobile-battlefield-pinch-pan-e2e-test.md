# 大杀四方移动端战场双指缩放 / 拖拽平移 E2E 证据

## 范围

- 任务：验证 `smashup` 在手机横屏下启用“战场局部 viewport 双指缩放 + 单指拖拽平移”后，是否只放大战场，不把 HUD / 手牌 / 结束回合按钮一起缩放。
- 结论：**达到本轮验收标准。**
- 执行命令：

```bash
npm run test:e2e:ci:file -- smashup-4p-layout-test.e2e.ts "移动端横屏应保持四人局布局可用，并支持手牌长按看牌与战场拖拽放大"
```

## 我实际查看的截图

### 1. `04-mobile-landscape-layout.png`

- 我实际看到：手机横屏默认态下，三块基地与其下方卡牌横向排开，右侧圆形“结束回合”按钮、左下牌库、顶部回合/记分板、底部两张手牌同时可见。
- 我实际看到：默认态战场没有被额外放大，主战场和 HUD 处于同一常规布局关系，用户不需要先缩放才能找到主操作按钮。
- 验收判断：**达到默认态验收标准。**

### 2. `04d-mobile-battlefield-pinch-zoom.png`

- 我实际看到：双指缩放后，三块基地和基地区卡牌明显放大，占据了更多横向视野；这证明放大作用在战场 viewport，而不是整页 UI。
- 我实际看到：右侧“结束回合”按钮仍保持原来的圆形尺寸和右侧锚点，没有跟着战场一起变大或漂到中间。
- 我实际看到：底部两张手牌仍保持原始尺寸和底部位置，没有随着战场缩放一起被放大。
- 验收判断：**达到“只缩战场、不缩 HUD/手牌”的验收标准。**

### 3. `04e-mobile-battlefield-panned.png`

- 我实际看到：放大后的战场被向左拖拽后，左侧基地已有一部分移出视口，说明平移确实发生在战场内容上，而不是页面本身滚动。
- 我实际看到：右侧“结束回合”按钮依旧固定在右侧；左下牌库、底部手牌也仍留在原位置，说明平移没有把外围 UI 一起带走。
- 验收判断：**达到“缩放后可拖拽平移，且外围 UI 不受影响”的验收标准。**

### 4. `13-desktop-end-turn-restored.png`

- 我实际看到：PC 参考图中，主战场、手牌、结束回合按钮的相对关系与移动端默认态一致，都是“战场居中、手牌在底部、结束回合按钮独立悬浮在右侧”。
- 我实际看到：手机横屏不是另一套完全不同的结构，而是沿用同一套主关系，只是视口更紧凑。
- 验收判断：**达到“保持 PC 同构关系、不另起一套移动布局”的验收标准。**

### 5. `11-mobile-hand-inspect-button-magnify.png`

- 我实际看到：手牌放大仍然可用，放大卡面位于屏幕中央，背景里的战场与结束回合按钮仍各自在原本区域。
- 我实际看到：新增战场 pinch/pan 没有破坏既有手牌看大图能力。
- 验收判断：**达到“通用战场缩放不回归已有单卡放大”的验收标准。**

## 无效 / 不作为主收口的截图

### `04c-mobile-end-turn-restored.png`

- 我实际看了这张图，但它**不作为本轮主收口证据**。
- 原因：这张图里“结束回合按钮恢复后”的视觉证明不够直接，肉眼没有 `04d` / `04e` 那么清晰，单独拿它收口说服力不足。
- 处理方式：本轮主结论改由 `04d-mobile-battlefield-pinch-zoom.png`、`04e-mobile-battlefield-panned.png` 与 `04-mobile-landscape-layout.png` 共同证明。

## 最终结论

- `smashup` 已可在手机横屏下使用战场局部 `pinch + pan`。
- 从截图可见，缩放和平移都只作用于基地战场区域，没有把手牌、顶部记分板、牌库、右侧“结束回合”按钮一起缩放或带偏。
- 现有手牌看大图能力仍正常，因此这次接入可以视为**安全加回真实战场拖拽放大**，且口径符合“已有整块棋盘/战场放大能力的游戏除外；`smashup` 可纳入框架接管，`dicethrone` 维持 `game-owned`”。
