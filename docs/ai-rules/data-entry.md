# 数据录入规范

> **适用范围**：本规范是根级通用规范，适用于所有游戏、所有由图片、规则书、Wiki、截图驱动的业务数据录入任务。
>
> **边界**：本文件只定义所有游戏共用的录入流程、来源优先级、核对契约和零猜测原则；任何游戏专属字段、卡牌结构、抓取站点、抓取脚本、索引口径，都必须写到该游戏自己的 `rule/` 文档或专项规范中。

## 一、通用规范定义

- 根 `AGENTS.md` 与 `docs/ai-rules/` 中的规范，默认都是全游戏通用规范。
- 通用规范只能约束方法、流程、验证和文档要求，不能直接绑定某个游戏的局部数据结构。
- 某个游戏的特例、字段命名、卡牌类型、索引来源、抓取脚本，只能作为“游戏专属补充规范”存在，不得直接写成全局默认。
- 根级文档允许引用游戏专属条目，但必须显式标明作用域。凡是出现具体 `gameId`、具体来源站点、具体字段结构的内容，都必须写清“仅适用于哪个游戏或模块”。
- 当通用规范与游戏专属规范冲突时：
  1. 通用规范负责方法论和流程。
  2. 游戏专属规范负责该游戏的具体数据口径。
  3. 不得因为某个游戏当前任务方便，就把其局部约定提升成全局要求。

## 二、核心原则

- 先建契约，后写代码：录入前必须先产出 Markdown 核对契约，再落运行时代码。
- 单一权威来源：每个字段都要能追溯到当前权威来源。
- 零猜测：任何文字、数字、关键词、索引、限定词，只要不确定，就必须停止录入。
- 原文与结构化结果并存：必须同时保留原始文本和结构化字段，禁止只保留最终代码值。
- 先文档后实现：影响规则、机制、描述或展示的数据录入，必须先更新文档，再开始实现。

## 三、权威来源优先级

默认优先级如下：

1. 官方勘误、官方规则书、官方 PDF
2. 官方数据库、官方页面、官方 API
3. 项目约定的专用抓取源
4. 用户提供的清晰图片、截图、资料
5. 项目内既有规则文档

补充规则：

- 如果用户明确要求“以这批图片为准”，则这些图片在当前任务里可以成为该字段的直接权威来源，但必须显式记录这一点。
- 如果某个游戏要求必须走专用爬虫或专用比对脚本，应在该游戏专属规范中写明，并作为该游戏的第 3 优先级来源。

## 四、标准流程

### 1. 锁定来源

必须先记录：

- 来源类型
- 来源路径或链接
- 获取时间
- 字段适用范围

### 2. 建立 Markdown 核对契约

录入前必须先写表格，至少包含：

| 字段 | 含义 |
| --- | --- |
| 实体标识 | `defId`、`id`、变体 ID |
| 来源定位 | 图片路径、裁图路径、页码、URL |
| 原始名称 | 原图或原文中的名称 |
| 原始文本 | 原图或原文中的完整描述 |
| 结构化字段 | `type`、`cost`、`power`、`tags`、`index`、`faction` 等 |
| 不确定项 | 看不清、冲突、待确认字段 |
| 结论状态 | `已确认`、`待确认`、`冲突待裁定` |

强制要求：

- 表格必须按素材顺序、逻辑顺序或官方顺序排列。
- 原始文本必须和结构化字段并排出现。
- 同一字段如果存在多个来源，必须在表格里显式写出对照结论。

### 3. 全口径核对

至少逐项核对：

- 名称
- 类型
- 数值
- 关键词
- 限定词
- 作用对象
- 作用范围
- 时机
- 次数限制
- 例外条件
- 图片索引、图集索引、资源路径

### 4. 结构化映射

必须明确区分：

- 哪些字段进入静态数据层
- 哪些字段进入 i18n
- 哪些字段进入规则文档
- 哪些字段只作为后续实现依据

### 5. 文档同步

录入影响玩法、机制、文案或资源展示时，必须同步更新：

- 对应游戏的 `rule/*.md`
- 对应 i18n 文案
- 必要时的开发规范文档

### 6. 再进入代码实现

只有在以下条件满足后，才允许开始实现：

- 来源已锁定
- Markdown 核对契约已完成
- 不确定项已清零或显式挂起
- 文档已同步

## 五、图片文字辨识零猜测原则

以下任一情况都必须停止：

- 名称有字看不清
- 数值模糊
- “可 / 必须 / 改为 / 额外 / 其他 / 另一个 / 直到”等限定词不确定
- 图片索引、裁片顺序、图集位置不确定

禁止行为：

- 根据英文原版猜中文
- 根据上下文补句子
- 根据相邻卡牌推断索引
- 先录入再回头核对

## 六、图片与索引录入规则

如果素材涉及 atlas、index、crop，必须额外记录：

- 原始大图路径
- 裁图路径
- 裁图顺序依据
- 最终运行时索引字段

如果索引尚未确认：

- 可以先录文字字段
- 但必须把索引标记为未确认
- 不得把猜测值写成正式值

## 七、最低交付物

一次完整的数据录入任务，最低应交付：

1. 权威来源记录
2. Markdown 核对契约表
3. 同步后的规则或说明文档
4. 结构化数据录入
5. 必要的验证结果

如果只完成了第 4 步，没有前 1 到 3 步，则视为录入不完整。
