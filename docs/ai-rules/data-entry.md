# 数据录入规范

> **适用范围**：本规范是根级通用规范，适用于所有游戏、所有由图片、规则书、Wiki、截图驱动的业务数据录入任务。
>
> **边界**：本文件只定义所有游戏共用的录入流程、来源优先级、核对契约和零猜测原则；任何游戏专属字段、卡牌结构、抓取站点、抓取脚本、索引口径，都必须写到该游戏自己的 `rule/` 文档或专项规范中。

## 一、通用规范定义

- 根 `AGENTS.md` 与 `docs/ai-rules/` 中的规范，默认都是全游戏通用规范。
- 通用规范只能约束方法、流程、验证和文档要求，不能直接绑定某个游戏的局部数据结构。
- 某个游戏的特例、字段命名、卡牌类型、索引来源、抓取脚本，只能作为“游戏专属补充规范”存在，不得直接写成全局默认。
- 根级文档允许引用游戏专属条目，但必须显式标明作用域。凡是出现具体 `gameId`、具体来源站点、具体字段结构的内容，都必须写清“仅适用于哪个游戏或模块”。
- 当通用规范与游戏专属规范冲突时：
  1. 通用规范负责方法论和流程。
  2. 游戏专属规范负责该游戏的具体数据口径。
  3. 不得因为某个游戏当前任务方便，就把其局部约定提升成全局要求。

## 二、核心原则

- 先建契约，后写代码：录入前必须先产出 Markdown 核对契约，再落运行时代码。
- 先切图，后录入：原始整图只能用于定位，不得直接拿整张合图或整页截图做正式录入主表。
- 真相源与对照源分离：真相源负责正式录入，对照源只负责辅助核对与发现冲突。
- 单一权威来源：每个字段都要能追溯到当前任务约定的主真相源。
- 零猜测：任何文字、数字、关键词、索引、限定词，只要不确定，就必须停止录入。
- 原文与结构化结果并存：必须同时保留原始文本和结构化字段，禁止只保留最终代码值。
- 先文档后实现：影响规则、机制、描述或展示的数据录入，必须先更新文档，再开始实现。
- 表格对人友好：如果当前任务约定“以汉化图为真相源”，则主表、切图表、冲突表都必须优先展示汉化版本数据，不能要求审阅者先对照英文原版才能审核。

## 三、录入对象范围

录入任务默认必须覆盖“该素材承载的全部对象”，不能只录技能名或伤害摘要。至少检查以下对象：

- 能力类：普通技能、防御技、被动、终极技、升级差异、触发图标、时机标签、伤害类型。
- 状态类：Token 提示板、堆叠上限、施加条件、移除条件、结算时机、持续时间、例外条件。
- 提示类：说明板、帮助板、关键词提醒、骰面说明、流程提示、特殊裁定提示。
- 资源类：atlas 图、atlas json、frame 命名、独立 icon、资源引用路径、复用关系。
- 索引类：大图路径、裁图路径、排序依据、运行时索引字段、图块编号、UI 显示映射。

强制要求：

- 每个技能条目都必须同时记录：
  - 触发条件或触发时机。
  - 汉化图可见原文或完整转录。
  - 结构化结论。
- 不得只写“效果摘要”而省略触发条件。
- 不得只录技能而漏掉提示板、图集索引、资源复用说明。

## 四、权威来源优先级

默认优先级如下：

1. 官方勘误、官方规则书、官方 PDF
2. 官方数据库、官方页面、官方 API
3. 项目约定的专用抓取源或游戏专属爬虫
4. 用户明确指定为本轮真相源的清晰图片、截图、扫描件
5. 项目内既有规则文档
6. Wiki、社区资料、论坛整理

补充规则：

- 如果用户明确要求“以这批汉化图片为准”，则这些图片在当前任务里就是直接真相源；英文原版、Wiki、社区资料只能作为辅助对照，不得进入主真相源表的主列。
- 如果某个游戏要求必须走专用爬虫或专用比对脚本，应在该游戏专属规范中写明，并作为该游戏的第 3 优先级来源。
- 游戏专属规范可以参考其他游戏的抓取流程，但不得把某个游戏的专用脚本硬写成所有游戏的全局默认。
- Wiki 永远不是默认真相源；除非用户明确重新指定，否则只能作为对照来源。

## 五、强制交付物

一次完整的数据录入任务，至少要有以下文档产物：

1. 真相源表
2. 切图表
3. 核对合同表
4. Wiki / 对照源对照表
5. 冲突待裁定表

### 1. 真相源表

必须记录：

- 真相源类型
- 真相源路径或链接
- 获取时间
- 覆盖对象
- 录入口径说明

### 2. 切图表

必须记录：

- 原图路径
- 裁图路径
- 裁图坐标或裁图规则
- 对应对象
- 当前可读性结论

### 3. 核对合同表

录入前必须先写表格，至少包含：

| 字段 | 含义 |
| --- | --- |
| 实体标识 | `defId`、`id`、变体 ID |
| 类别 | 技能 / 状态 / 提示 / 图集 / 索引 |
| 真相源定位 | 图片路径、裁图路径、页码、URL |
| 原始名称 | 原图或原文中的名称 |
| 触发条件 / 时机 | 图标组合、阶段、前置条件、次数限制 |
| 原始文本 | 原图或原文中的完整描述 |
| 结构化字段 | `type`、`cost`、`power`、`tags`、`index`、`faction` 等 |
| 不确定项 | 看不清、冲突、待确认字段 |
| 结论状态 | `已确认`、`待确认`、`冲突待裁定` |

### 4. 对照表

必须记录：

- 对照源链接或路径
- 对照源版本语言
- 对照到的字段
- 对照结果：`一致`、`补充说明`、`疑似冲突`

### 5. 冲突待裁定表

一旦主真相源与对照源冲突，必须单独建表，至少包含：

- 冲突对象
- 真相源结论
- 对照源结论
- 冲突类型：文字 / 数值 / 时机 / 范围 / 索引 / 资源引用
- 当前处理状态：`待用户裁定`

禁止行为：

- 发现冲突后直接选一个来源写进代码。
- 在主表中偷偷用对照源覆盖真相源。
- 把“我觉得更合理”写成裁决结论。

## 六、标准流程

### 1. 锁定主真相源与对照源

必须先记录：

- 真相源类型
- 真相源路径或链接
- 对照源类型
- 对照源路径或链接
- 获取时间
- 字段适用范围

### 2. 先裁图到可读粒度

必须先把整图切到“单个对象能完整看清”的粒度，再开始录入：

- 单个技能一张裁图
- 单个状态说明一张裁图
- 单个提示板块一张裁图
- 单个 atlas frame 或复用说明单独登记

强制要求：

- 裁图必须覆盖完整标题、触发条件、正文、图标和关键限定词。
- 如果整图上多个对象混在一起，必须拆开，不能依赖放大整页查看。
- 如果裁图后仍看不清，必须继续细分或更换更清晰来源。

### 3. 建立 Markdown 核对契约

- 表格必须按素材顺序、逻辑顺序或官方顺序排列。
- 原始文本必须和结构化字段并排出现。
- 同一字段如果存在多个来源，必须在表格里显式写出对照结论。

### 4. 全口径核对

至少逐项核对：

- 名称
- 类型
- 数值
- 关键词
- 限定词
- 作用对象
- 作用范围
- 触发条件
- 触发时机
- 次数限制
- 例外条件
- 图片索引、图集索引、资源路径、复用来源

### 5. 结构化映射

必须明确区分：

- 哪些字段进入静态数据层
- 哪些字段进入 i18n
- 哪些字段进入规则文档
- 哪些字段进入资源注册或 atlas/json
- 哪些字段只作为后续实现依据

### 6. 文档同步

录入影响玩法、机制、文案或资源展示时，必须同步更新：

- 对应游戏的 `rule/*.md`
- 对应 i18n 文案
- 必要时的开发规范文档
- 资源索引说明或素材登记

### 7. 再进入代码实现

只有在以下条件满足后，才允许开始实现：

- 真相源已锁定
- 切图已完成并能看清
- Markdown 核对契约已完成
- 对照表已完成
- 不确定项已清零或显式挂起
- 冲突项已登记
- 文档已同步

## 七、图片文字辨识零猜测原则

以下任一情况都必须停止：

- 名称有字看不清
- 数值模糊
- “可 / 必须 / 改为 / 额外 / 其他 / 另一个 / 直到 / 改为 / 不能 / 仍然”等限定词不确定
- 图标触发条件看不清
- 图片索引、裁片顺序、图集位置不确定

禁止行为：

- 根据英文原版反推中文主表
- 根据上下文补句子
- 根据相邻卡牌推断索引
- 先录入再回头核对
- 用 Wiki 文本替代汉化图中看不清的字段却不登记冲突

## 八、Wiki 与对照源使用规则

- Wiki、社区页面、论坛讨论只能进入“对照表”，不能直接替代主真相源。
- 如果 Wiki 提供的是补充裁定而非原文重印，必须标记为“补充说明”，不能伪装成原图文本。
- 如果 Wiki / 英文图与汉化图一致，可以记录为“一致”。
- 如果 Wiki / 英文图补充了汉化图未写出的判例，可以记录为“补充说明”，后续再判断是否需要进规则文档。
- 如果 Wiki / 英文图与汉化图在数值、时机、对象、索引、触发条件上不一致，必须进入“冲突待裁定表”。

## 九、图片与索引录入规则

如果素材涉及 atlas、index、crop，必须额外记录：

- 原始大图路径
- 裁图路径
- 裁图顺序依据
- atlas / json 路径
- frame 名称与坐标
- 最终运行时索引字段
- 是否复用其他图集或资源

如果索引尚未确认：

- 可以先录文字字段
- 但必须把索引标记为未确认
- 不得把猜测值写成正式值

## 十、最低交付标准

以下任一情况，都视为录入不完整：

- 只改了代码，没有真相源表
- 只看整图，没有切图表
- 只写效果摘要，没有触发条件
- 只录技能，没有录提示板 / atlas / 索引
- 用 Wiki 直接替代真相源
- 发现冲突但没有单独冲突表
