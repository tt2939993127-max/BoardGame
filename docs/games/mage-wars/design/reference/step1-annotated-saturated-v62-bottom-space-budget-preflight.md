# Mage Wars v62 底部空间预算前置回执

> 状态：`preflight-ready / open-design-artifact-only / media-generate-forbidden / implementation-blocked-until-user-approval`。本文件只服务 v62 Open Design artifact 设计稿；不批准真实 Board/UI 实现、真实运行页 E2E 或移动端适配。

## 本轮问题裁定

| 项 | 内容 |
| --- | --- |
| 用户问题 | `下面为什么空这么多` |
| 现实后果 | v61 底部牌桌边缘存在大块无职责空白，玩家会觉得当前可支配法术书被悬在画面中部，而不是贴近自己的操作区 |
| 直接证据 | v61 原图中法术书候选卡下沿约在底边上方，底部剩余空间没有承载法术书分页、已计划法术、弃牌堆、回合结束或安全区证据 |
| 设计归因 | v61 把法术书卡牌改为 `120x169` 后，只验证了不重叠和卡牌尺寸，没有重新分配底边空间；这是 `space-budget-failed`，不是合格留白 |
| 当前结论 | v61 的 `AI_PASS` 必须撤销，状态改为 `REVISE / dead-space-failed / space-budget-failed` |

## v62 空间预算规则

| 区域 | 预算职责 | v62 处理 |
| --- | --- | --- |
| 底部 0-40px | 桌面边缘 / 视觉缓冲 | 可保留极窄缓冲，但不得形成无对象大片空地 |
| 底部 40-95px | 回合结束、弃牌堆、法术书页码和容量读数 | 必须贴近底边，承担真实操作或归档入口职责 |
| 底部 95-285px | 法术书候选与已计划法术 | 当前可支配对象主承载区；卡牌必须可读，不得缩回小牌 |
| 竞技场下沿低权重纹理 | 可被法术书 overlay 覆盖 | 只保护 A3 / B3 场上实体、区域归属、token 和骰子；不保护空石砖纹理 |
| 右下角 | 已计划法术、弃牌堆、回合结束 | 不得空置；但也不得新增规则未授权的确认 / 执行 / 取消 |

## v62 设计动作

- 法术书整体下沉：把 `.book-browser` 从 v61 的 `top:704px` 下移到贴近底边的操作带。
- 法术书候选继续保持 `8 / 页`，卡牌尺寸不低于 v61 的 `120x169`；允许小幅提升到约 `130x183`，但不得形成 v56 的常驻巨牌。
- 分页 rail 跟随法术书卡列下沉，贴近右侧页边，不悬在中部空地。
- 法术书容量读数下沉到卡列下方，作为底边空间的一部分，而不是悬在牌列和底边之间。
- 已计划法术、弃牌堆和回合结束整体压到底部右侧，形成连续操作边，而不是让右下角留下无职责空白。
- 不新增阴影托盘、玻璃壳、解释正文、确认 / 执行 / 取消按钮。

## v62 出图硬禁止

- 禁止把 v61 底部空白解释为安全区，除非有真实系统安全区证据。
- 禁止为了消除空白新增无规则职责的黑影、纸托盘、玻璃面板或大色块。
- 禁止把法术书候选缩小到不可读；底部空间应优先兑现给卡牌可读性和分页可达性。
- 禁止把弃牌堆做成显眼正面牌或主舞台对象；它仍是公开归档入口。
- 禁止出现 `手牌 / 确认 / 执行 / 取消 / 10 / 页 / 1 / 3`。
- 禁止让法术书、已计划区、弃牌堆、回合结束压住场上实体、B2 目标、骰子、伤害 token、燃烧 token 或区域归属。

## v62 AI 核验门

- 图片加载必须全部成功。
- 法术书当前页必须有 8 张正式卡图，页码 `1 / 4`，容量 `法术书 30`、`8 / 页`。
- 法术书卡必须可读，常驻尺寸不低于 v61；选中态不得改变常驻布局占位。
- 底部无职责空白必须明显减少，底边空间至少被法术书候选、分页、容量读数、已计划法术、弃牌堆或回合结束占用。
- 关键规则对象必须守恒：骰子、效果骰、伤害 token、燃烧 token、守卫 token、行动 / 快速施法 token、法术书、已计划法术、弃牌堆和对手已计划卡背都必须可见。
- AI 图面核验 PASS 后，才允许在本对话内展示原始 PNG 给用户看；不使用 PureRef，不进入真实实现。
