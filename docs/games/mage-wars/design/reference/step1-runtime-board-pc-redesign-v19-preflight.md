# Mage Wars Step 1 PC 设计稿 v19 前置证据

> 状态：`consumed-by-v19-ai-pass / media-generate-forbidden / preflight-only`。本文件只锁 v19 设计稿启动前提，不是设计稿，不是实现批准，也不是人工验收图；当前可送人工验收的是 `step1-runtime-board-opendesign-artifact-v19.png` 及其审计文件。

## 本轮结论

- `page_004.md` 明确学徒模式使用 `2x3` 格区域竞技场，并忽略另一半竞技场；v19 必须先呈现 6 个可读区域。
- `page_007.md` 明确标准版图共 12 个“区域”，相邻只按水平 / 垂直共享边；区域是移动、射程与目标判断单位，不是装饰分割线。
- `page_024.md` 明确近战攻击目标必须与攻击方处于同一格区域；法师、生物、魔物和当前目标必须有唯一所属区域。
- `page_027.md` 明确状态标记放置在目标对象上；伤害、守卫、燃烧、束缚等 token 必须贴附宿主卡，不得漂在格线、骰盘或其它 UI 上。

## v18 撤销原因

- 西锁骑士中心点落在 A2 / B2 缝隙，不能判断唯一所属区域。
- 火印魔婴与烈焰魔物出现在 2x3 学徒半场之外，违反“只使用一半竞技场”和“场上对象属于区域”的前提。
- 缠绕藤蔓虽然中心点大致在 B3，但可见包围盒大面积压入相邻区域，低于 `apprentice-zone-layout-contract.md` 的面积阈值。

## v19 启动合同

- 坐标源：`docs/games/mage-wars/design/implementable/apprentice-zone-layout-contract.md`。
- 区域结构：`2列 x 3行`，区域 ID 为 `A1/B1/A2/B2/A3/B3`。
- 对象落位：每张 `.field-card` 必须声明唯一 `data-zone-id`，中心点必须在对应区域内部。
- 面积阈值：可见包围盒至少 `85%` 在所属区域内，相邻区域重叠超过 `12%` 判失败。
- 贴附规则：伤害、状态、守卫、目标高亮、行动标记和快速施法标记必须贴附宿主对象，不得成为独立漂浮 UI。
- 核心结算落位：当前攻击骰、效果骰、命中、伤害和状态结果必须锚在目标区域附近、来源到目标的路径附近，或竞技场主舞台上层；右侧栏、日志栏、玩家牌区旁和空白角落只能存放结算后的摘要 / 回看。
- 视觉表达：区域边界应来自棋盘素材、地砖缝、轻微光照或低干扰热区；不得用厚边框、框中框或抽象六宫格替代正式竞技场。

## 召唤师战争只提供交互不变量

- 可参考：先划格、对象在格内、点击对象本体、弃牌堆在所属玩家边缘作为归档入口。
- 不可复制：召唤师战争的皮肤、牌区名称、卡图语义、底部手牌概念或召唤/移动规则。
- Mage Wars 设计稿必须以自己的规则名为准：法术书、已计划法术、弃牌堆、隐性结界、场上生物 / 魔物 / 法师、当前攻击 / 施法目标。

## DiceThrone 只提供骰子交互不变量

- 可参考：当骰子是当前步骤的主对象时，骰子本体必须成为玩家视线焦点，具备可点击 / 选中 / 结果反馈，并与当前目标或动作舞台相连。
- 不可复制：DiceThrone 的 3D 街机皮肤、英雄面板、锁骰 / 重掷规则、骰盘常驻位置和骰子尺寸。
- Mage Wars 设计稿必须把“一次攻击投掷”表达为目标对象上的临时结算层：骰面、伤害 / 致命伤害、效果骰和目标状态必须在同一视觉链路里。

## v19 出稿前检查

1. Open Design artifact 不得调用 `od media generate`，只允许 artifact 代码设计稿与正式素材输入链。
2. 截图审计必须输出 6 个区域 rect，以及每张场上卡的中心点、所属区域、区域内面积占比和跨区面积占比。
3. 骰盘 / 当前结算层必须在主舞台上层、目标附近或来源附近，但不得把目标卡挤出所属区域；审计必须输出骰盘到目标卡中心的距离、骰盘是否进入右侧栏 / 牌区 / 日志区，以及是否遮挡目标卡、token 或确认入口。
4. 对手隐藏信息只显示卡背 / 数量 / 控制归属，不得公开未揭示卡名或正面。
