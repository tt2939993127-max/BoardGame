# Mage Wars v63 分页比例前置回执

> 状态：`preflight-ready / open-design-artifact-only / media-generate-forbidden / implementation-blocked-until-user-approval`。本文件只服务 v63 Open Design artifact 设计稿；不批准真实 Board/UI 实现、真实运行页 E2E 或移动端适配。

## 本轮问题裁定

| 项 | 内容 |
| --- | --- |
| 用户问题 | `页码占据这么大空间合理吗` |
| 正确理解 | 页码 / 翻页有职责，但 v62 把分页做成了过高的独立 rail，视觉占比过大，导致法术书卡牌下方形成一条空槽 |
| 我上一轮错误 | 我把用户标注误解成“屏幕底边空白 / 无职责空白”，并错误说成“页码没有职责” |
| 现实后果 | 玩家第一眼会看到法术书下方一整条空区和孤立分页，而不是连续的法术书页边 / 牌列 |
| v63 修法 | 分页控件压缩成贴近牌列底边的小型页脚控件；法术书卡牌列下移，占用原空槽；容量文字和页码不再共同撑出一条大栏 |

## v63 分页比例规则

| 对象 | v62 问题 | v63 裁定 |
| --- | --- | --- |
| 页码 `1 / 4` | 有职责，但独立 rail 高 `190px`，超出职责需要 | 改为约 `50x28` 的紧凑页码 |
| 翻页按钮 | 两个 `42x42` 按钮竖向撑满大区域 | 改为约 `34x34` 小按钮，与页码水平排列 |
| 法术书卡牌 | 卡牌下方留出空槽给分页 / 容量 | 卡牌列下移，底边贴近页脚 |
| 容量文字 | 放在空槽左侧，和页码共同制造大底栏 | 仍保留，但只作为短页脚，不承担大容器占位 |
| 浏览器命中区 | 透明但实际撑出大空白感 | 视觉上只让卡牌、分类、页脚控件承担空间 |

## v63 出图硬禁止

- 禁止把分页职责扩大成整条大空栏。
- 禁止说“页码没有职责”；正确问题是职责与视觉占比不匹配。
- 禁止为了修分页而缩小法术书候选卡；候选卡仍必须保持 `130x183` 左右。
- 禁止增加无语义托盘、阴影、玻璃壳或解释正文。
- 禁止出现 `手牌 / 确认 / 执行 / 取消 / 10 / 页 / 1 / 3`。
- 禁止让法术书、分页、已计划区、弃牌堆、回合结束压住场上实体、B2 目标、骰子、伤害 token、燃烧 token 或区域归属。

## v63 AI 核验门

- 图片加载必须全部成功。
- 法术书当前页必须有 8 张正式卡图，页码 `1 / 4`，容量 `法术书 30`、`8 / 页`。
- 分页控件必须是紧凑页脚控件，不再作为高 rail 占据大块空间。
- 法术书卡牌下方不能再有一条明显空槽；下方只允许短页脚和必要桌边缓冲。
- 关键规则对象必须守恒：骰子、效果骰、伤害 token、燃烧 token、守卫 token、行动 / 快速施法 token、法术书、已计划法术、弃牌堆和对手已计划卡背都必须可见。
