## 规则到画面结论

| 规则 / 规范结论 | 影响主体 | v29 设计决策 / 禁止项 |
| --- | --- | --- |
| 学徒模式当前法术来自“已计划法术”，不是规则外手牌 | 已计划火球术、法术书候选 | 火球术只在已计划法术中承担当前来源；法术书候选是可浏览对象，不抢施法来源 |
| 学徒竞技场是 `2列 x 3行` 六区域，场上对象必须有唯一所属区域 | 竞技场、生物、目标和 token | 继续保留 v20+ 的 6 区域锚点和卡牌入格几何门禁 |
| 当前状态是火球术目标 / 结算链 | 西锁骑士、火球术、骰子、伤害 / 燃烧 token | 火球术来源、费用和目标状态贴近已计划火球术；骰子和结果继续贴目标附近 |
| UI 允许有职责的重叠 | 法术书、已计划法术、候选牌 | 法术书作为贴底 overlay 轻压桌面 / 棋盘下沿低权重区域；不再机械避开底图 |
| 规则没有证明“施放前必须确认” | 确认 / 取消按钮 | 删除常驻确认 / 取消；只保留费用和目标短状态，动作由已计划火球术 / 合法目标承接 |

## 层级表

| 层 | 对象 | 允许重叠 | 必须保护 |
| --- | --- | --- | --- |
| 背景 / 桌面 | 暗色桌面、未用半场退场阴影 | 可被边缘 HUD 和牌区 overlay 轻压 | 不作为主交互 |
| 棋盘 / 区域 | 标准竞技场、右半场 6 区域 | 可被低权重状态和牌区边缘轻压 | 区域名、区域边界、当前目标所在格 |
| 实体对象 | 场上卡、法师牌、token、卡背 | 可被目标高亮、结算 token 局部覆盖 | 卡牌归属、目标本体、资源和状态读数 |
| 主交互 overlay | 法术书候选、已计划法术、当前火球术来源 | 可轻压桌面和棋盘下沿低权重区域 | 不能遮挡场上目标 / 骰子 / 当前结算 |
| 结算 overlay | 攻击骰、效果骰、伤害 / 燃烧 token | 可高于棋盘和卡牌 | 必须锚在目标 / 来源链路，不进侧栏 |
| 辅助 HUD | 双方法师状态、附件、弃牌入口 | 贴所属玩家边缘 | 不抢当前施法链 |

## 确认控件裁定

| 问题 | v29 裁定 |
| --- | --- |
| 确认前玩家还能改变什么？ | 当前稿没有规则证据证明存在可撤销目标、多目标分配、费用选择或响应分支 |
| 确认后系统发生什么？ | 当前状态已进入火球术目标 / 结算表达，继续显示确认会伪造一步规则外流程 |
| 为什么不能点击对象本体完成？ | 当前主语是已计划火球术和合法目标，应由火球术卡、目标高亮、费用 / 目标短状态承接 |
| 是否允许常驻确认 / 取消？ | 不允许。只有后续实现证明存在真实选择态或网络提交状态时，才允许临时出现 |

## 前置硬失败禁止清单

- 出现规则不存在的手牌 / hand / opponent-hand。
- 常驻显示确认 / 取消 / 提交 / 下一步，但没有规则或真实系统状态授权。
- 为了不和底图重叠，把法术书、已计划法术、当前来源、骰盘或结果反馈挤到角落 / 无关空白。
- 右下 / 底边 / 侧边空白没有职责，却让重要交互为它让位。
- 法术书 overlay 遮挡目标卡、骰子、状态 token 或区域归属。
- 用户批准前启动真实 Board/UI、真实页面 E2E 或移动端。
