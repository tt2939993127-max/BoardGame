## v26 人工失败转设计规则

| 用户反馈 | v27 设计裁定 | 禁止项 |
| --- | --- | --- |
| “边框都加上了” | 底部法术书不再画封闭 rail / 面板 / 牌托框；只保留卡牌、书堆、页签和轻标签 | 大底板、圆角容器、描边、内外阴影、玻璃板 |
| “沉浸感有什么误解” | 沉浸感定义为桌游对象本体成为 UI：卡牌和书页直接摆在桌面上，而不是装进后台控件 | 用 UI 容器承载主体、素材被框体降级 |
| “确认使用的位置真的需要吗，放计划是不是更好” | 费用 / 确认 / 取消跟随“已计划法术 / 火球术”来源槽，成为计划槽动作条 | 右下孤立确认面板、远离当前施法来源 |

## 框体职责回执

| 常驻框体 / 底板 | v27 裁定 |
| --- | --- |
| 底部法术书 rail 大容器 | 删除视觉容器；保留不可见语义容器用于排版和几何审计 |
| 法术候选卡 | 直接摆在桌面下沿，轻微旋转和投影表达实体卡 |
| 已计划法术 | 直接显示两张计划牌，火球术高亮为当前施放来源 |
| 确认动作条 | 贴近已计划火球术；按钮只保留必要底板和 44px 命中区 |
| 分类 / 分页 | 降为小书签 / 页签，不做一排后台筛选胶囊 |

## 前置硬失败禁止清单

- 出现规则不存在的手牌 / hand / opponent-hand。
- 底部出现封闭大容器、可见边框、玻璃板或厚底板。
- 费用 / 确认 / 取消仍停在右下孤立动作面板。
- 当前火球术同时作为候选和已计划来源重复出现。
- 攻击骰、伤害、燃烧离开西锁骑士目标附近。
- 用户批准前启动真实 Board/UI、真实页面 E2E 或移动端。
