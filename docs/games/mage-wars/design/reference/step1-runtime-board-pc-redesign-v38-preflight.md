## v37 降级原因

| v37 现象 | v38 修正 |
| --- | --- |
| 机器几何通过，但玩家任务链未证明 | 审计必须写“来源对象、目标、确认 / 取消、集合入口职责”四项玩家语言 |

## 阶段容量裁定

| 阶段 | 本稿是否展示 | 画面职责 |
| --- | --- | --- |
| 计划 / 浏览态 | 否 | 法术书需要分类、分页、候选卡和焦点预览；不得用本稿小入口证明计划态友好 |
| 目标确认态 | 是 | 当前来源火球术、已选 B2 西锁骑士、确认施放 / 取消选择、法力预扣 |
| 结算态 | 否 | 确认后才出现攻击骰、效果骰、伤害 / 燃烧 token；本稿不混入 |

## 规则到画面裁决

| 规则结论 | 画面主体 | v38 决策 |
| --- | --- | --- |
| 卡面已有费用、射程、目标栏、骰数和效果 | 火球术大卡 | 主 UI 不复写这些字段，只给来源卡、目标和确认状态 |
| 施法支付前可取消，支付后进入反制 / 结算 | 动作工作台 | 确认施放 / 取消选择与来源卡和目标摘要同组；确认后退场 |
| 法术书最多准备 2 张已计划法术 | 入口 rail | 当前已计划火球术为主；另一张计划卡可见；法术书入口不等于完整浏览器 |
| 对手已计划和隐性结界隐藏身份 | 对手卡背 / 附件卡背 | 只显示卡背、数量和归属，不公开卡名 |

## 前置硬失败禁止清单

- 不得出现手牌 / hand / opponent-hand。
- 不得把卡面已有费用、射程、目标栏、骰数或效果正文复写成 UI chip。
- 不得把确认态和结算态混在同一单态设计稿。
- 不得用目标确认态小入口冒充完整法术书浏览态。
- 不得把来源卡、目标摘要和确认 / 取消拆到两个无关视觉区域。
- 用户批准前不得进入真实 Board/UI、真实页面 E2E 或移动端。
