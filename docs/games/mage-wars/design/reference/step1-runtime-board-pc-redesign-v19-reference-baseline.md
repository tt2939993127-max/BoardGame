## Mage Wars v19 参考基线

1. 玩家 3 秒内必须看见：正式竞技场半场、六个区域、双方法师 / 生物、当前攻击目标、攻击骰 / 效果骰、伤害 / 状态结果。
2. 当前攻击投掷是核心交互，不是边缘摘要。骰子必须贴近目标、来源或来源到目标的路径；结算完成后才允许变成边缘摘要。
3. 场上卡牌必须有唯一 `zoneId`，玩家不能猜它属于哪格；自然旋转只允许在格内发生。
4. 牌区按 Mage Wars 规则命名：法术书、已计划法术、弃牌堆、隐性结界、场上卡；禁止出现规则不存在的手牌语义。
5. 归档 / 可检视对象如弃牌堆默认在所属玩家边缘，不进入中央主链路，除非当前规则步骤要求从中选择或结算。

## v18 到 v19 差距矩阵

| 基准要求 | v18 / 当前失败 | 玩家问题 | v19 修复落点 | 验收证据 |
| --- | --- | --- | --- | --- |
| 场上对象唯一归属区域 | 西锁骑士骑 A2/B2 线，火印魔婴和烈焰魔物在半场外，缠绕藤蔓压线 | 玩家无法判断近战、射程、目标是否合法 | `apprentice-zone-layout-contract.md` + artifact `data-zone-id` + 几何审计 | 每张 `.field-card` 中心入格，所属区域面积 ≥85%，相邻重叠 ≤12% |
| 当前攻击骰贴近目标链路 | v17 曾把攻击掷骰降到右侧，v18 虽回到主舞台但对象锚点失败 | 玩家看不出“谁被谁攻击、骰子为什么在那、结果作用到谁” | v19 临时结算层锚在目标卡附近或来源-目标路径上 | 审计输出骰盘到目标卡中心距离、遮挡检查、右侧栏排除 |
| 正式素材承担主语 | 历史稿反复出现面板 / 框体 / 圆点抢主语 | 第一眼像网页壳，不像 Mage Wars 对局 | 棋盘、法师牌、法术卡、token、攻击骰贴图、蓝色 d12 作为主体 | 随图素材账本 + 图面主体可见 |
| 归档对象低权重 | 历史稿把弃牌堆放进中间或靠近主链 | 低频检视对象被误读成当前行动 | 弃牌堆回所属玩家边缘，点击后 overlay 检视 | 设计稿图面中弃牌堆不在中央，不与确认 / 取消同权重 |
| 少边框 | 历史稿用框体解决分区 | 玩家先看到容器而非棋盘 / 卡牌 / 骰子 | 区域边界来自棋盘 / 材质 / 轻高亮；非交互边框删除 | AI 审计列出所有非素材边框职责，无法说明者为 0 |

## v19 不变量

- 竞技场是第一视觉主体；骰子 / 伤害 / 状态是攻击步骤的临时主层。
- 右侧栏只承载当前行动按钮、已结算摘要或详情入口；不得承载当前攻击投掷主结果。
- 所有能点击的主对象必须是对象本体或对应区域本体；代理按钮只能进入选择态或确认已选结果。
- 设计稿未通过 AI 审计和人工验收前，不得进入真实 Board/UI 实现、真实页面 E2E 或移动端适配。
