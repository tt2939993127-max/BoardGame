# 法师战争 v5 多设计稿前置说明

> 状态：`preflight-ready / open-design-artifact-only / media-generate-forbidden / implementation-blocked-until-human-approval`。本文件是本轮“先简述再生产”的前置回执；它不是人工验收图。

## 用户真实需求简述

用户要的不是继续微调旧稿，也不是把同一界面的几个阶段截图说成多方案。本轮要重新生产的是：

1. 先按 Mage Wars 规则推导 UI，不凭直觉复制其它游戏，不引入规则不存在的“手牌”。
2. 使用 Open Design artifact 代码设计稿路线；禁止 `od media generate`、imagegen、图片模型生图。
3. 产出 PC 桌面端多套独立设计稿候选，每套都是独立 HTML artifact 和独立 PNG。
4. 三套候选必须模拟同一个饱和对局状态，而不是不同流程阶段。
5. 候选要体现必须交互元素：法术书、已计划法术、目标选择、施放确认 / 取消、费用、隐藏信息边界、攻击骰 / 效果骰、伤害 / 燃烧反馈。
6. 用户人工批准前，不得实现真实 Board/UI，不得启动真实游戏页 E2E，不得做移动端适配。

## v4 降级原因

| 候选 | 失败点 |
| --- | --- |
| 棋盘优先 | 学徒半场仍被完整标准竞技场左半边拖累；右侧动作卡像后台面板；底部法术书壳过重 |
| 法术书工作台 | 底部法术书变成大卡墙，压缩主舞台；确认动作离目标过远 |
| 开放桌面 | 比前两张更开放，但仍有重复动作卡和下方壳层；施法链路被 UI 面板抢焦点 |

v4 因此保留为失败候选，不进入人工验收。

## 出图前硬约束

| 规则 / 素材结论 | 画面决策 |
| --- | --- |
| 学徒模式是 `2x3` 半场 | 不再展示完整无效左半场；六区域是第一视觉 |
| 规则没有“手牌” | artifact、class、aria、审计和汇报禁止出现手牌 / hand |
| 已计划法术最多 2 张 | 已计划法术比全法术书更靠近当前动作 |
| 弃牌堆是公开归档 | 只做所属玩家边缘入口，不进中央 |
| 攻击骰 / 效果骰是当前结算主体 | 必须贴近目标或施法链，不能放右侧栏、日志或底部工作台 |
| 对手隐藏信息不得泄露 | 对手计划和隐性结界显示卡背 + 数量，不显示卡名 |
| 棋盘、卡牌、牌背、token、骰子已有素材 | 这些主体必须使用 Open Design refs 中的真实素材 |
| 生命、法力、费用属于运行态读数 | 可用自制 UI，但必须贴近法师 / 当前法术，不能做粗糙蓝圆 |
