# 法师战争 v4 多设计稿前置说明

> 状态：`preflight-ready / open-design-artifact-only / media-generate-forbidden / implementation-blocked-until-human-approval`。本文件先把用户真实需求、v3 失败原因和 v4 生产口径落成可复查合同；它不是人工验收图。

## 用户真实需求简述

用户要的不是继续微调旧稿，也不是把同一套 UI 的不同阶段截图包装成多方案。当前需求是：

1. 先从 Mage Wars 规则和素材推导 UI 设计，不凭直觉画框。
2. 用 Open Design 产出 PC 桌面设计稿候选，不调用 `od media generate`，不走图片模型生图。
3. 同一个饱和对局状态下，给出多套独立 UI 设计稿，供人工比较和选择。
4. 多套稿必须是独立 artifact、独立 PNG、独立审计；总览页和同页缩略图不能冒充多稿。
5. 每套稿必须改变主焦点、信息架构、主要点击路径、空间比例和视觉语法中的至少三项。
6. 用户人工批准某一稿前，不得实现真实 Board/UI、不得启动真实游戏页 E2E、不得做移动端适配。

## v3 失败原因

| 问题 | 结论 |
| --- | --- |
| 三张图分别是施法结算、法术书计划、战场指挥 | 这是同一 UI 家族的三种阶段状态，不是三套独立设计方案 |
| 文件独立但设计轴没有独立 | 独立文件不等于独立方案；信息架构、空间比例和视觉语法仍过度同源 |
| 看起来像说明不同工作流 | 用户要看可选的主界面方案，不是阶段说明图 |
| 人工验收前曾被过早打开 | AI PASS 不能替代用户批准；失败候选不得继续送验 |

因此 v3 降为历史失败候选；v4 不继承它的“阶段稿”结构。

## v4 共同饱和状态

三张 v4 必须模拟同一局面，而不是不同阶段：

- 当前玩家：邪术师。
- 对手：女祭司。
- 当前动作：邪术师使用已计划法术 `火球术`，目标为女祭司侧 `西锁骑士`，处于支付前目标确认 / 结算预览。
- 竞技场：学徒 `2x3` 六区域，规则区域第一视觉清楚；所有场上卡牌有唯一所属区域。
- 场上对象：邪术师、女祭司、火烙魔婴、烈焰狱鬼、灰衣天使、西锁骑士、皇家箭手、缠绕藤蔓。
- 附件 / 状态：邪术师装备狱火长鞭并有隐性结界；女祭司装备风龙皮甲、偏移护腕并有隐性结界；西锁骑士带伤害；灰衣天使守卫；火烙魔婴带燃烧。
- 牌区白名单：法术书、已计划法术、弃牌堆、隐性结界卡背、公开场上法术 / 装备 / 生物。
- 隐藏信息：对手已计划法术和隐性结界只能显示卡背、数量、控制归属，不显示正面或卡名。

## 规则到画面硬约束

| 规则 / 素材结论 | 画面决策 |
| --- | --- |
| 学徒模式使用标准竞技场一半 `2x3` 六区域 | 中央必须能读出 6 个区域，卡牌不能骑线或跨格 |
| 法术书准备最多 2 张已计划法术 | 己方已计划法术必须比全法术书候选更靠近主动作 |
| 规则没有“手牌”主牌区 | HTML、class、aria、可见文字、审计和汇报都禁止出现手牌 / hand |
| 对手计划与隐性结界隐藏 | 对手只显示卡背、数量、位置，不泄露正面 |
| 攻击和效果骰是当前结算主体 | 骰子、伤害、燃烧必须贴目标或来源-目标链，不得放边栏、日志或底部工作台 |
| 棋盘、卡牌、法师牌、token、骰子已有正式素材 | 这些主体必须用真实素材；生命、法力、聚魔、费用可用自制运行态 UI |
| 弃牌堆是公开归档入口 | 只能贴所属玩家边缘或牌区旁，不能放中央成为主任务 |
| 常驻主 UI 不解释规则 | 只允许对象名、数字、短状态、按钮标签 |

## 出图 / 审计口径

- 生成路线：本地写 Open Design HTML artifact，再用 Playwright 导出 PNG。
- 禁止路线：`od media generate`、imagegen、图片模型、真实 Board/UI 实现、真实游戏页 E2E。
- AI 自审必须逐张看原图，不合格继续改，不打开给用户。
- AI PASS 后才允许按 `show-image-to-user` 流程把最终候选组打开给用户人工验收。
- v21 基线保留；v4 不覆盖 v21、v2、v3。
