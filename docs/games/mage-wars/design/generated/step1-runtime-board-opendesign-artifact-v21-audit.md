## 玩家友好性批判

| 细节 | 批判 | 裁定 |
| --- | --- | --- |
| 玩家面板姿态 | v20 的法师牌和状态组合有“整块玩家面板斜着”的感受，会降低读数稳定性。v21 把法师牌、生命条、法力条、聚魔读数全部水平化，玩家扫读更直接 | `PASS` |
| 生命 / 法力表达 | 只用彩色圆点会像占位，不像正式运行态 UI。v21 使用水平条 + 数值，学习的是成熟格子卡牌游戏的读数不变量，不复制皮肤 | `PASS` |
| 法术书承载量 | v20 的法术书只是小牌堆和 2 张已计划，无法表达“法术书很多、需要检索”。v21 底部展示候选卡行、分类和分页，能说明未来扩展到更多法术时的溢出策略 | `PASS` |
| 规则命名 | 用户说的是“像下面一排显示手牌那样好浏览”的体验诉求，但 Mage Wars 规则没有常规手牌区。v21 保留交互形态，正式文案全部使用法术书、候选、已计划 | `PASS` |
| 已计划来源 | 浏览器不能让玩家绕过计划阶段直接从全书施法。v21 仍用 `已计划 2/2` 承接当前可施放来源，并把火球术放在已计划槽 | `PASS` |
| 对手隐藏信息 | 法术书浏览器只在己方展开；对手侧只有法术书、已计划数量、弃牌堆和卡背，不泄露计划 | `PASS` |
| 中央竞技场 | 底部浏览器增加信息密度，但没有压住六区域、目标、骰盘或确认区；主舞台仍然是竞技场 | `PASS` |
| 底部贴边 | 候选卡距底部 22px，偏紧但未截断；作为 PC 设计稿可以送验，若用户要求更松可下一版把浏览器整体上移 8-12px | `PASS-WITH-NOTE` |

## 收口结论

- 规范确实需要更新，已回代到项目 UI 设计 skill 和 Mage Wars 专项设计合同：大型私有法术书允许使用底部浏览器、分类和分页，但不得改名为规则没有的牌区。
- v21 解决了用户最新反馈的三个硬点：玩家状态 HUD 不斜、生命 / 法力改成水平可读条、法术书改成底部候选浏览 + 分类 + 分页。
- v21 继续保留 v20 已通过的核心结构：学徒 `2x3` 区域先成立、场上卡牌单一区域归属、攻击骰 / 效果骰贴近 B2 目标。
- v21 可作为当前 PC Open Design 人工验收候选；用户明确批准前，仍禁止进入真实 Board/UI 实现、真实页面 E2E 或移动端适配。
