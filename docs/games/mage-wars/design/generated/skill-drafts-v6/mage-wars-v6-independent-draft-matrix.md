# 法师战争 v6 独立 Open Design 设计稿矩阵

> 状态：`REVISE / same-shell-failure / human-review-blocked`。v6 不覆盖 v21 基线、不覆盖 v5 历史候选；本批只生成 Open Design artifact 和导出 PNG，未调用 media 生图，未进入真实 Board/UI 实现。用户反馈三稿“大差不差”后，v6 的多方案裁定撤销；本文件保留为失败复盘输入。

## 用户需求执行口径

- 多套独立设计稿，而不是同页缩略图或同母版微调。
- 同一饱和交互局面：邪术师用已计划 `火球术` 指向女祭司侧 `西锁骑士`，攻击骰 / 效果骰 / 伤害 / 燃烧贴目标链路。
- 规则牌区只使用法术书、已计划法术、弃牌堆、隐性结界卡背和公开场上卡牌。
- PC 端设计稿未获用户批准前，真实实现、真实页面 E2E 和移动端均冻结。

## 失败复盘

| 用户真实要求 | v6 实际做到的 | 失败结论 |
| --- | --- | --- |
| 多个真正不同的设计稿 | 三个独立 HTML / PNG，但都沿用同一棋盘、同一 HUD、同一火球术结算线和同一边缘卡区 | 文件独立，不等于设计独立 |
| 不能只换优先级 | 只把棋盘、法术书、施法链的权重前后挪动 | 属于同母版权重变化 |
| 需要先能比较哪套最好 | 三张第一眼都像同一游戏壳的不同截图 | 不足以支撑选择 |
| 基于规则重构 UI | 保留了规则白名单和素材，但没有重做空间模型 / 信息架构 | 规则正确性不能替代设计差异 |

## 差异矩阵

| 维度 | 竞技场战术桌 | 法术书底部浏览器 | 开放施法链路 |
| --- | --- | --- | --- |
| 第一视觉 | 2x3 区域与场上卡牌 | 底部法术书分类 / 分页 / 已计划槽 | 来源法师 -> 火球术 -> 骰子 -> 目标 |
| 主点击路径 | 点已计划法术，再点棋盘目标，目标旁确认 | 浏览法术书和已计划槽，再回棋盘目标确认 | 从来源法师沿施法链看目标、骰子和确认 |
