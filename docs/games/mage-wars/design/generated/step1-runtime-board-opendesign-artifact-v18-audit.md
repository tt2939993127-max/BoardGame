# 法师战争 Step 1 PC Open Design v18 图面审计

> 结论：`AI_PASS_REVOKED / zone-anchoring-failed / human-review-blocked / implementation-blocked / mobile-blocked-by-desktop`。v18 已撤销人工验收资格：它修正了骰盘在边栏的问题，但没有证明场上对象归属于单一竞技场区域；玩家会看到卡牌骑在区域中线、格外或未使用半场上。

## 撤销原因

| 对象 | 几何复核 | 玩家问题 | 裁定 |
| --- | --- | --- | --- |
| 西锁骑士 | 中心点 `x=1181,y=451` 落在 A2 / B2 之间的 `11px` 缝隙；包围盒约 `47.0%` 在 A2、`41.1%` 在 B2 | 当前攻击目标到底属于 A2 还是 B2 不可辨；近战同区、范围和状态归属都会被误读 | `REVISE` |
| 火印魔婴 | 中心点 `x=952,y=658` 在网格外；包围盒只少量压到 A2 / A3 | 场上对象看起来不属于任何区域 | `REVISE` |
| 烈焰魔物 | 包围盒没有命中任何 `.zone-cell` | 对象摆在学徒 2x3 区域合同之外 | `REVISE` |
| 缠绕藤蔓 | 中心点在 B3，但包围盒约 `13.5%` 压入 B2、仅 `78.4%` 在 B3 | 宿主区域大致可读但仍低于区域内锚定阈值 | `REVISE` |

本轮补充裁定：Mage Wars 的场上法师、生物、魔物、结界宿主和目标对象必须有唯一所属区域。允许轻微旋转和自然偏移，但对象中心不得落在区域边界或缝隙上，卡牌大部分可见面积必须在所属区域内部。缺少 `区域 -> 对象锚点 -> token 附着点` 合同时，Open Design artifact 不能给 `AI_PASS`。

## 人工验收边界

- v18 不再允许打开给用户人工验收；此前打开行为只保留为历史候选记录。
- 用户明确批准前，仍冻结 Board/UI 实现、真实页面 E2E 和移动端适配。
- 下一版必须先建立学徒 `2x3` 区域坐标 / 锚点合同，再重构 Open Design artifact；不得继续沿 v18 只调卡牌坐标。
