## 规则到画面结论

| 规则 / 合同结论 | 画面主体 | B 方案设计决策 / 禁止项 |
| --- | --- | --- |
| 学徒法师每回合从法术书准备最多 2 个法术；未施放法术回到法术书 | 底部法术书工作台 + `已计划 2 槽` | 已计划槽必须独立、固定、比普通候选更强；不能把候选卡误认为都可直接施放 |
| 法术书是私有检索对象，对手不能得知计划 | 己方法术候选、对手卡背 / 数量 | 己方可见候选正面；对手只显示卡背、数量和归属，不显示候选、不显示卡名 |
| 学徒法术书固定为预设牌库：兽王 33 张，女祭司 / 邪术师 / 巫师各 30 张 | 分类 / 分页 / 候选容量 | 工作台必须表达“大型但受控的私有库”，用分类与分页降噪，不做自由构筑 UI |
| 卡牌字段包含费用、类型 / 学派、等级、射程、目标、攻击条和正文 | 候选卡、当前选中卡、字段短标签 | 不能用纯文字列表替代卡牌；可在工作台给短字段 chip，但长规则正文不常驻 |
| 当前行动只能施放已计划法术 | 当前施法槽、已计划槽、费用预扣 | 选中 `火球术` 后从已计划槽抬升到棋盘下沿，不能从全书候选直接施法 |
| 学徒竞技场是 `2列 x 3行` 半场；距离按水平 / 垂直区域 | 上方竞技场 `A1-B3` 区域 | 即使 B 强化底部，所有场上卡中心仍必须在唯一所属区域内，不得骑线或落格外 |
| 攻击骰 / 效果骰是当前目标结算反馈 | 目标附近骰盘 / 伤害 token | 骰子必须靠近目标或来源，不得进入工作台、右侧栏、日志栏或按钮区 |
| 法师状态板只作为规则参考 | 法师 HUD 水平条、法力条、聚魔短读数 | 主界面不出现整张状态板或状态板裁切；动态读数使用 `approved-programmatic-runtime-ui` |
| 弃牌堆公开可检视，但通常不是当前可施放来源 | 工作台角落 / 玩家边缘入口 | 弃牌堆必须低权重、可点击展开；当前无回收 / 复活 / 选择规则时不得进入中央 |

### 尺寸建议

| 区域 | 目标尺寸 / 占比 | 设计说明 |
| --- | --- | --- |
| 上方竞技场 | 约 `1180-1260w x 650-700h` | 棋盘仍是规则空间主体；不得低于可清楚辨认 `2x3` 和 8 个场上对象的尺度 |
| 底部法术书工作台 | 约 `1600-1760w x 300-340h`，贴底但保留 20px 安全边距 | 作为 B 方案第一差异；全宽工作台，不是小浏览条 |
| 候选卡横排 | 6-8 张，单张最小约 `86x122`，当前页可横向扫描 | 卡牌必须是真实裁图或 atlas crop，不用文字卡壳 |
| 已计划槽 | 2 槽，每槽大于普通候选 15-25% | 强调“当前可施放来源”，不得混入候选池 |
| 分类 / 分页控件 | 命中区按 44px 级别设计 | 分类和分页是实际控件，不是装饰标签 |
| 行动 dock | 工作台右侧或右上角，确认 / 取消稳定 | 只承载按钮、费用预览、短状态；不承载骰子主结果 |

## 法术书工作台组成

| 组件 | 可见内容 | 交互职责 | 禁止项 |
| --- | --- | --- | --- |
| 分类栏 | `全部 / 攻击 / 结界 / 生物 / 魔物 / 装备 / 咒语` | 降低 30+ 张法术选择负担 | 不得只做静态装饰；选中态要明显 |
| 候选卡池 | 当前分类下 6-8 张候选卡 | 浏览和选择将要准备的法术 | 不得让玩家误以为候选都可立刻施放 |
| 分页 | `‹ 1/4 ›` 或等价可点控件 | 表达法术书容量和溢出策略 | 不得使用小到不可点的文字 |
| 已计划槽 | 最多 2 张，本人可见正面 | 当前回合真正可施放来源 | 不得命名为“手牌”；不得和候选池混在一起 |
| 当前施法槽 | 选中已计划法术后抬升 | 连接来源法师、目标和费用 | 不得成为遮挡棋盘的大卡墙 |
| 弃牌堆入口 | 公开数量、所属玩家、卡背或顶牌 | 公开归档检视 | 不得进入中央主链，除非当前规则步骤要求 |
| 费用 / 资源反馈 | 法力预扣、行动 / 快速施法消耗 | 让确认前代价清楚 | 不得离开当前卡和法师法力条太远 |
| 短状态 | `计划阶段`、`可快速施法`、`等待反制` | 状态可见 | 不得写规则说明长句或验收文案 |

## 隐藏信息和命名红线

- 可见文案、class、aria、审计文本禁止出现：`手牌`、`hand`、`opponent-hand`、`默认持牌区`。
- 正式名称只用：`法术书`、`法术候选`、`已计划法术`、`弃牌堆`、`隐性结界`、`公开场上法术 / 装备 / 生物 / 魔物`。
- 对手法术书不展示候选，不展示卡名；只展示卡背、数量、控制归属。
- 主 UI 常驻文字只允许对象名、数值、短状态、按钮标签；规则说明、教程句、验收句不得进入画面。

## 交互 storyboard

### 计划阶段

1. 玩家打开底部法术书工作台。
2. 使用分类切换到 `攻击` 或 `结界`。
3. 在候选卡池中选择 `火球术` 和 `法师祸咒`。
4. 两张卡进入 `已计划 2/2`，工作台显示法力预估和计划完成状态。
5. 对手侧只出现 2 张计划卡背和数量。

### 行动 / 施法阶段

1. 工作台从计划态压缩，但保留候选、分类、分页和已计划槽。
2. 玩家点击已计划槽中的 `火球术`。
3. `火球术` 抬升到竞技场下沿，费用预扣贴近卡牌和邪术师法力条。
4. 棋盘合法目标本体高亮；非法目标保留可见但降噪。
5. 玩家点击西锁骑士，目标附近显示攻击骰 / 效果骰和短结果。
6. 右侧 / 工作台 dock 只显示确认、取消和短状态；确认后支付前可取消，支付后进入反制或结算。
