# 法师战争 UI 设计合同

> **gameId**：`mage-wars`
> **当前阶段**：OpenSpec `add-mage-wars-foundation` 已获用户批准；当前 PC 设计目标为 Open Design v75。继续设计或进入真实 Board/UI 实现前，必须同时消费规则/素材前置矩阵与用户纠正覆盖账本。
> **设计路线**：使用 Open Design artifact，不使用 `od media generate` / imagegen 生图；v75 之外的旧 Open Design / HTML 预览只保留为失败或历史证据，不得恢复为当前验收或实现依据。
> **基础风格来源**：`tactical-clean` 的信息密度 + `classic-parchment` 的实体卡牌/规则书质感。不得复刻 TTS 桌面风格。

---

## 1. Spec

### 目标用户

- 两名在线玩家进行法师竞技场决斗。
- 首轮默认服务学徒/基础预设法术书，不服务完整自由构筑。

### 本界面要完成的现实任务

- 让玩家在同一个桌面视图里理解：当前阶段、当前行动者、可行动对象、可施放法术、目标区域/对象、结算结果。
- 让施法成为画面主事件：来源、目标、路径/扩散、命中/结算结果必须可见。
- 保护隐藏信息：对手不能看到自己的法术书、计划法术和未展示结界身份。

### 主路径

1. 准备环节：起始、重置、聚魔、维持、计划、部署。
2. 行动环节：优先快速施法、生物行动、最终快速施法。
3. 玩家选择法术或行动对象。
4. UI 高亮合法区域/目标。
5. 命令验证通过后播放对应 FX。
6. 状态、伤害、魔力、行动标记、结界/装备附件同步更新。

### 必须覆盖状态

- 空态：刚建局、资源尚未加载时显示加载/待入座，不显示假素材。
- 等待态：等待对手计划、等待响应、等待结算动画完成。
- 错误态：非法施法、目标移动导致取消、资源不足、目标不合法。
- 权限态：旁观者默认看玩家 0 或当前回合玩家视角；不能泄露隐藏信息。
- 完成态：一方法师死亡，显示胜者与最终状态摘要。

### 验收标准

- 桌面 1920x1080 首屏内完整显示竞技场、双方状态、当前主动作、法术书、已计划法术、弃牌堆和附件入口。
- 常驻主 UI 不出现规则解释正文，只出现对象名、数值、短状态和动作按钮。
- 同一步只保留一个主交互焦点；提示层不能遮住棋盘、法术书入口、已计划法术槽、弃牌堆或目标对象。
- 场上法师、生物、魔物和当前目标必须有唯一所属区域；卡牌中心点不得落在区域边界、区域缝隙或未使用半场上。
- 法术 FX 只由已验证规则事件驱动，失败命令不能播放成功态。
- `board-ui-preflight-matrix.md` 必须先判定所有可见对象的素材状态和允许表达；矩阵未过时，本合同只作方向约束，不作为出图或实现批准依据。
- `external-ui-methodology-baseline.md` 必须先把外部 UI / UX 书籍和规范转成玩家任务、交互权重、命中区、少边框和多方案差异门禁；未消费该基线时，不得继续从旧 Open Design artifact 微调。

## 2. Reference

### 成熟基线

- 实体桌游桌面：中央竞技场是第一眼主体；法师牌、自制状态 HUD、法术书入口、已计划法术、弃牌堆和标记围绕棋盘服务。
- 卡牌战棋电子游戏：选中准备就绪的法师或生物后，合法移动格和攻击目标只在棋盘本体高亮；点落点移动、点敌方对象攻击，不另造常驻确认入口。
- 选中单位的规则独有自我动作（例如守卫）只允许贴在该单位附近的局部控件中；右侧只保留阶段、结束回合和低频入口，不得承接移动、攻击或守卫选择。
- 骰子只在真实攻击事件发生时，于攻击来源与目标之间或目标区域上层短暂显示；伤害与状态 token 持续贴在受影响单位本体，不得作为静态棋盘摆件。
- 本仓交互来源以 `design-system/game-ui/source-families.md` 为准；不得继承其它游戏的卡图、牌区名称或“手牌”语义。

### 当前素材第一眼信号

- `标准竞技场` 图片是主棋盘视觉真相源。
- `法师牌 atlas`、`通用卡背`、状态 token、攻击骰贴图是首轮运行时素材来源。
- `法师状态板` 只作 `reference-only`：用于 setup、轨道坐标、规则详情或帮助回看，不作为 Step 1 主界面玩家血量 / 法力面板。
- TTS/Workshop 只回答对象关系和素材索引，不回答最终 UI 风格。

### 差距矩阵

| 当前状态 | 风险 | UI 合同 |
| --- | --- | --- |
| 规则对象已经抽出，但素材未落盘 | 容易用程序化占位冒充正式资源 | 未落盘对象只能显示 `in_progress`，不能宣称素材完成 |
| Workshop 有大量卡牌实例 | 容易把重复实例当正式卡表 | 先锁学徒清单和 atlas frame，再进数据层 |
| 法术特效是用户硬需求 | 容易被当成后续 polish | FX descriptor 进入规则事件合同 |
| 隐性结界/计划法术复杂 | 容易在 UI 泄露身份 | UI 必须先区分本人/对手/旁观者可见层 |
| 旧 UI 预览未重读规则真相源 | 容易把旧截图和旧 PASS 当作当前证据 | 设计稿 / 预览 / AI 核验前必须重新读取规则合同和素材矩阵 |
| 临时裁图被用于视觉预览 | 容易把录入证据误当正式素材 | `temp/` 裁图只能做录入核对，验收稿必须使用正式落盘、压缩和可追溯 atlas/frame |

## 3. Domain

| 规则对象 | UI 语义 | 禁止混用 |
| --- | --- | --- |
| 法师 | 双方核心场上单位、资源池、装备/结界宿主；与生物一样占据区域、可被选中、可移动、可成为攻击目标 | 不从棋盘移到只读 HUD，也不把 HUD 提示卡当法师本体 |
| 法术牌 | 私有法术书、已计划法术、弃牌堆、场上生物 / 装备 / 结界 / 魔物 | 不用文字壳替代已有卡图；规则没有“手牌”时禁止引入手牌区 |
| 竞技场区域 | 移动、距离、目标选择、范围和墙体边界 | 不用自由坐标临时摆放；不让卡牌骑在两个区域中间 |
| 生物/魔物 | 区域内可行动对象，有行动标记和状态 | 不把多个单对象压成 count |
| 装备 | 附着到法师的公开附件，有槽位限制 | 不和状态 token 混成一类 |
| 结界 | 可隐藏的附件，有展示费用和触发时机 | 不公开对手看不到的身份 |
| 状态 token | 守卫、燃烧、腐化、眩晕、昏迷、沉睡等 | 不用普通 badge 代替正式 token |
| 运行态状态 HUD | 生命、伤害、法力、聚魔、费用预扣等动态读数 | 不贴整张状态板或状态板裁切；不脱离法师对象做纯文字资源栏 |
| 法师状态板 | setup / 轨道坐标 / 规则详情来源 | 不作为主对局常驻可见主体；不替代自制血条 / 蓝条 / 聚魔读数 |
| 法术 FX | 规则事件的视觉投影 | 不由按钮点击直接播放成功态 |

## 3.1 区域锚点合同

- 下一版设计稿必须读取 `docs/games/mage-wars/design/implementable/apprentice-zone-layout-contract.md`。
- 学徒竞技场按 `2列 x 3行` 半场设计；区域 ID 为 `A1/B1/A2/B2/A3/B3`，字母为列、数字为行。
- 每张场上卡牌必须在 artifact 中声明唯一 `zoneId`，并落在对应区域主 / 次锚点内。
- 卡牌中心点必须在所属区域内部；旋转后的可见包围盒至少 `85%` 在所属区域内，相邻区域重叠超过 `12%` 直接判失败。
- token、伤害、守卫、状态和目标高亮必须贴附宿主对象，不得漂在区域边线、骰子、侧栏或其它对象上。
- 可以参考召唤师战争的“格子先行、对象在格内、点击对象本体”交互不变量；不得复制其皮肤、牌区名称或卡牌语义。

## 3.2 规则对象交互权重

本节是后续 Open Design artifact、位图设计稿和真实 Board/UI 的共同前置。规则对象“存在”只说明它必须被表达或可访问，不说明它应占据中央或常驻展开。

| 规则对象 | 当前施法态权重 | 默认位置 | 展开方式 | 规则依据 / 玩家友好结论 |
| --- | --- | --- | --- | --- |
| 竞技场 | 主舞台 | 中央最大面积 | 常驻 | 学徒模式使用 `2x3` 半场，移动、距离、目标与对象都发生在区域中；玩家第一眼应看到棋盘和目标。 |
| 当前施放法术 | 主动作 | 已计划法术槽抬升到施法链 | 当前步骤展开 | 规则要求只能施放本回合准备的法术；来源必须从“已计划法术”进入当前施法，而不是从规则不存在的手牌进入。 |
| 当前目标 | 主动作 | 竞技场对象本体 | 对象高亮 / 点击对象 | 规则要求宣告合法目标、范围和目标类型；玩家应直接看目标本体，不靠代理列表。 |
| 骰盘 | 当前攻击 / 附加效果的主结算反馈 | 目标区域上层、来源与目标连线附近，或目标卡旁的轻量落点；不得离开竞技场主舞台 | 投掷 / 结果时展开，结算后降为摘要 | 一次攻击投掷是当前动作核心：玩家正在问“谁打谁、掷了什么、造成什么”。骰盘必须把攻击骰、效果骰、目标卡和伤害 / 状态贴成一条链；放到右侧栏、角落或牌区旁会切断因果，直接判 `REVISE`。 |
| 法术书 | 计划 / 检索态主浏览对象；施法态次级私密入口 | 所属玩家底部边缘，靠近已计划法术 | 底部一排候选卡 + 分类切换 + 分页；施法态可压缩但不能消失 | 法术存放在法术书中，计划阶段最多选 2 张；法术书规模超过单屏承载，玩家需要像浏览卡列一样快速检索，但正式 UI 名称必须是“法术书 / 法术候选”，不能命名为规则不存在的牌区。 |
| 已计划法术 | 当前可支配对象 | 所属玩家边缘，靠近当前行动 | 最多 2 槽常驻 | 本回合准备的法术可被施放；本人可见正面，对手只见卡背 / 数量。 |
| 弃牌堆 | 公开归档入口 | 所属玩家边缘，靠近法术书但低于已计划法术 | 点击后 overlay 检视 | 规则写明弃牌堆可随时检视，但其中卡牌是已消耗、通常不能取回；当前施法态没有从弃牌堆选择 / 回收 / 复活 / 结算的规则步骤时，不得放入中央或靠近施法主链。 |
| 隐性结界 | 宿主附件 / 响应对象 | 附属目标旁，按视角显示卡背或正面 | 展示或触发时抬升 | 隐性结界展示前对手不知道身份；必须贴宿主，不应放进通用手牌或中央牌堆。 |
| 行动 / 快速施法标记 | 行动权限反馈 | 法师牌附近 | 常驻短反馈 | 它们决定当前能否行动 / 快施，应贴法师对象，不做成通用开关。 |
| 生命 / 法力 / 聚魔 / 伤害 | 持续读数 | 法师牌附近，水平状态条贴对象 | 常驻轻量 | 状态板只作 reference-only；动态读数用自制条和短数字，不能复现整张状态板。玩家面板不得斜放或跟随法师牌倾斜，关键数值必须水平、稳定、可扫读。 |

### 法术书浏览器回代

- 计划 / 检索态必须允许玩家从法术书快速找到卡牌：底部至少展示一排候选卡、规则分类切换、页码以及上一页 / 下一页按钮；候选卡数量按 1920x1080 可读尺寸决定，不能用小牌堆角标替代浏览。
- 分类按钮使用规则类型语义，例如 `攻击`、`结界`、`生物`、`魔物`、`装备`、`咒语`；不确定类型进入后续术语表统一，不能先发明通用牌区。
- `已计划 0-2` 是真正的当前可施放来源；法术书浏览器负责检索和准备，不直接让玩家从全书绕过计划阶段施放。
- 对手侧只能显示法术书存在、数量、已计划数量、公开弃牌堆和必要卡背；不能把对手法术书浏览器展开为可读卡名或正面卡牌。
- 施法态可以保留底部浏览行的压缩版本，帮助玩家理解“这张火球术来自已计划法术”；但当前行动焦点仍是已计划法术、目标本体直选、费用预扣反馈与骰盘。没有规则授权时，不显示常驻确认 / 执行 / 取消。

### 玩家状态 HUD 回代

- 玩家状态 HUD 必须是水平承载：生命条、法力条、聚魔短读数、行动 / 快速施法标记都不得旋转；法师牌允许极轻微桌面自然倾斜，但不得让玩家误认为整块面板是斜的。
- 生命 / 法力可参考成熟格子卡牌游戏的“条形 + 数值 + 资源色”交互不变量：清晰条形、当前数值、最大值或伤害差额可扫读；不得复制其它游戏皮肤，也不得退成普通彩色圆点。
- 状态 HUD 必须贴近对应法师牌，避免成为脱离法师对象的仪表盘；若空间冲突，优先压缩装饰和边框，不压缩数值可读性。

### 召唤师战争对比边界

- 允许抽取的交互不变量：弃牌堆作为所属玩家边缘入口，点击后展开检视；阶段按钮和牌堆不抢中央棋盘。
- 允许抽取的格子不变量：规则格子先于对象摆放，单位 / 卡牌在格内，合法目标直接在格子或对象本体高亮，点击本体完成选择。
- 允许抽取的状态不变量：玩家血量 / 资源用贴近玩家对象的水平条形和数字表达，读数稳定、无需解释，且不抢中央格子。
- 禁止继承的内容：召唤师战争的皮肤、牌区名称、卡牌语义、中心布局或“手牌”概念。
- 结论：Mage Wars 的弃牌堆存在，但在当前施法态只是已消耗公开归档区；放到中间不是易于交互，而是把低频检视对象提升成了错误主焦点。

### DiceThrone 对比边界

- 允许抽取的交互不变量：当骰子是当前步骤的核心对象时，骰子本体必须可点击、可选中、有结果反馈，并处在当前动作舞台或主对象附近；边栏只适合常驻骰盘、偏好设置、历史摘要或非阻塞检视。
- 禁止继承的内容：DiceThrone 的 3D 街机风格、英雄面板皮肤、锁骰 / 重掷规则、骰子尺寸和布局比例。
- 结论：Mage Wars 一次攻击投掷不是装饰性随机结果，而是战斗步骤中的主反馈。攻击骰 / 效果骰可以是临时上层，但不能因为想保持画面干净而移到右侧辅助区。

### 3.3 失败稿回代规则

- 任何稿件里只要把弃牌堆放进中央施法链、放在目标选择工作台附近、或做成与当前目标同等重量，直接判 `REVISE`；修法不是调小，而是回到所属玩家边缘归档入口。
- 任何稿件里只要把法术书退化为小牌堆角标、没有底部浏览候选、没有分类切换或没有分页策略，直接判 `REVISE`；修法是建立法术书浏览器和已计划槽的双层结构，而不是把全书改名成其它牌区。
- 任何稿件里只要玩家状态 HUD 倾斜、关键数值跟着法师牌旋转、或生命 / 法力退成普通彩色圆点，直接判 `REVISE`；修法是水平状态条贴近法师，不是加框或加说明文字。
- 任何稿件里只要场上卡牌中心落在区域边界 / 区域缝隙 / 未使用半场，或玩家不能一眼判断目标属于哪个区域，直接判 `REVISE`；修法是重建区域锚点，不是继续微调阴影或边框。
- 任何稿件里只要当前攻击骰、效果骰、命中 / 伤害 / 治疗结果离开目标 / 来源 / 主舞台链路，进入右侧栏、日志栏、牌区旁或空白角落作为主承载，直接判 `REVISE`；修法是重建结算落位，不是把骰盘变大、加框或加箭头。
- 程序化运行态 UI 只允许承载动态读数和反馈。费用、法力、生命、伤害、效果骰可以自制，但必须先说明规则来源、对象锚点、形状材质和状态变化；普通蓝圆、默认圆点、随机胶囊、无材质数字球直接判 `REVISE`。
- 与召唤师战争对比时，只能抽“牌堆归属玩家边缘 + 点击展开检视”这类交互不变量；不得复制其视觉皮肤、中心布局、牌区名称或卡图语义。
- 若当前稿第一眼看到的是面板、边框、彩色圆点或说明文字，而不是竞技场、卡牌、法师和当前施法对象，必须整稿重构，不能继续在失败稿上微调。

## 4. Template

### 桌面布局

| 区域 | 位置 | 职责 |
| --- | --- | --- |
| 中央竞技场 | 画面中心，最大视觉面积 | 学徒 `2列 x 3行` 半场、区域锚点、法师/生物/墙体/目标高亮 |
| 玩家法师状态 HUD | 底部左/右或棋盘两侧靠近各自起始角，贴近法师牌，水平排布 | 自制生命条、伤害读数、法力蓝条、聚魔短读数、行动/快速施法；关键读数不得斜放 |
| 对手法师状态 HUD | 顶部左/右或棋盘两侧靠近对手起始角，贴近法师牌，水平排布 | 对手公开状态，不显示私密计划，不展示状态板原图；关键读数不得斜放 |
| 阶段 / 回合结束槽 | 右侧偏下固定槽 | 当前阶段、结束回合和必要短状态；不得承接单位移动、攻击、守卫、目标选择、骰子或当前结算 |
| 法术书浏览 / 已计划法术区 | 底部所属玩家边缘，候选行贴近已计划法术 | 法术书候选一排、分类按钮、分页按钮、最多 2 张已计划法术；当前选中法术可抬升到施法链 |
| 弃牌堆入口 | 所属玩家边缘，贴近法术书但低于当前可行动作 | 公开归档入口，点击后展开检视；当前步骤无回收/选择证据时不得进入中央 |
| 附件区 | 贴近对应法师牌 / 自制状态 HUD | 装备、结界、状态 token，隐藏/展示分层 |
| FX 层 | 棋盘上方独立 overlay | 施法来源、目标锁定、路径、命中反馈 |

### 移动/平板方向

- 首轮以桌面合同为权威。
- 移动端先声明 `landscape-adapted + board-shell`，后续单独验证；不得为手机反向压缩桌面棋盘。
- 错向提示只能非阻断；不能全屏挡住游戏。

## 6. Design

### 视觉气质

- 魔法竞技场、奥术仪式、实体桌游卡牌质感。
- 中央棋盘保持沉浸；HUD 稳定、克制、低框感。
- 主题色不做单一紫蓝：以深炭黑、古铜金、羊皮纸暖白、奥术蓝、火焰红、毒雾绿形成多色语义。

### Token

```css
--mw-bg-table: #15110d;
--mw-bg-panel: rgba(24, 22, 18, 0.86);
--mw-parchment: #e8d8b7;
--mw-ink: #2d2117;
--mw-brass: #b88a3d;
--mw-arcane: #4aa3ff;
--mw-fire: #e35b2f;
--mw-life: #4fbf6b;
--mw-shadow: #6f4aa8;
--mw-danger: #c93434;
--mw-border-soft: rgba(232, 216, 183, 0.22);
```

### 密度与形状

- 卡牌、棋盘格、token 是实体边界；UI 容器只做轻量组织。
- 主桌面禁止多层大框、黑色说明卡、重复胶囊壳。
- 主按钮 44px+ 命中区；动作文案 2-5 个中文字符优先。
- 正文规则只进帮助/详情层；主界面只保留短状态。

### 状态 HUD 语法

- 生命 / 伤害：贴近法师牌的细长生命条和伤害短数值，颜色从生命绿、伤害红和卡牌金属边推导。
- 法力 / 聚魔：贴近法师牌的蓝条与聚魔短读数，允许费用预扣用浅蓝虚线或短飘字表达。
- 行动 / 快速施法：优先用正式行动标记、快速施法标记或来源锁定 token；不能用普通灰 chip。
- 状态板：只在 setup、帮助、详情抽屉或规则回看里出现；主对局第一屏不得出现整张状态板、状态板裁切或状态板轨道皮肤。
- 几何姿态：HUD 整体和每条数值必须水平；法师牌轻微倾斜只能表达实体卡自然摆放，不能带歪 HUD、按钮或状态条。

### 骰子语法

- 攻击骰：`attack-die-texture.png` 是正式视觉基底；前端可用 canvas / sprite / Three.js 皮肤生成骰面，但玩家看到的骰面必须继承这张贴图的符号和材质。
- 效果骰：Workshop 已锁定为蓝色 `Die_12`；可程序化建模和投掷，但必须表现为蓝色 12 面效果骰，不能退成普通 D6。
- 分层边界：物理、随机、点击命中和重投选择层可以程序化；正式可见骰面不能是默认数字骰、纯文本公式、黑盒骰盘或通用骰子组件皮肤。
- 交互反馈：可点击、选中、重投、命中结果必须贴在骰子本体或落点附近，用轻量发光、停靠阴影、短飘字表达；不得用方框、包边、独立黑色面板或日志替代骰子反馈。
- 空间边界：攻击 / 效果结算中的骰子必须由真实规则事件触发，并在目标区域附近或来源到目标的主舞台路径上短暂出现；不得无事件常驻，也不得放在右侧栏、角落摘要、日志区或玩家牌堆旁作为当前主反馈。结算完成后才允许降级成边缘摘要。

### 少边框规则

- 允许的边界：素材自带印刷边、棋盘区域边界、卡牌 / token 本体边、当前合法目标的轻量高亮、必要按钮底板。
- 禁止的边界：为了分区而叠加的大面板、框中框、厚边框、玻璃仪表盘、把素材包成装饰角标的容器壳。
- 如果去掉某个框后真实对象和点击关系仍然清楚，该框默认删除；如果必须保留，必须能说清它保护哪个真实交互对象。

## 7. Craft

- 第一眼必须看到“中央竞技场 + 两名法师 + 当前阶段”，不是看到面板网格。
- 法术 FX 分四段：起手 150-250ms、目标锁定 150ms、路径/扩散 300-500ms、命中反馈 200-350ms。
- 动效只绑定事件流，不绑定 optimistic click success。
- 隐藏信息用牌背、锁形状态、私密边框区分；不在对手视角暴露真实卡名。
- 没有正式素材时，不用“缺图/待补”上屏；在文档和测试里记录缺口。

| --- | --- | --- |
| 主对象 | 竞技场、法师牌、当前行动状态和真实卡牌 / token 是第一视觉主体 | blocking |
